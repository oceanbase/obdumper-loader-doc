# 导数工具 V4.3.2

本次 10 月发版的导数工具 V4.3.2 旨在修复无主键无分区表导出不完整且无报错的问题，以及修复若干已知问题。

## 版本信息

* 当前版本：V4.3.2

* 发版时间：2024 年 10 月 31 日

## 新增功能

* 新增 `--source-type hive` 参数，支持从 Hive 存储路径中识别分区信息进行导入。

* 新增 `--auto-comlumn-mapping` 参数，支持列名自动映射，此时将根据源文件的列名和目标表列名进行对应导入，允许数据文件和目标表列数量不一致。目前支持的文件格式包括 CSV、Parquet 和 ORC。

* 支持 ORC、Parquet 的复杂类型。
  
* 新增 `--mem 4G` 参数指定内存大小，替代现有修改 JVM 参数的方式，更为友好。

* 通过参数 `-Denable.parallel.write=true` 开启并行写功能，导出后会将文件合并成单文件。

* 优化 CSV 解析效率，相比之前提高约 30%。

* 新增 Azure Blob、GCS 云存储支持，适配华为云 OBS 并行桶，实现主流云对象存储全兼容。

* 新增支持增量旁路模式，复用 `--direct` 参数，根据目标表是否已存在数据判定使用全量或增量模式。

* 扩展 `--file-regular-expression` 参数，支持从文件名提取库名和表名，实现多表导入。

## 兼容性变动

OBLOADER 解析 CSV 时默认 escapeCharacter 由 '\' 变更为 null，以符合标准 CSV 规范。

## 修复的问题

* 导入时 `--retry` 重试机制不可用。

* 导入单文件同时指定 `--table '*'` 可能导入错误表。

* Oracle 模式 JSON 类型导出格式错误。

* OBDUMPER 同一个表导出的文件包含二级名称，导致 OBLOADER 不能导入。

* 通过服务端旁路导入 40 亿行数据出现计数溢出。

* 服务端和导数工具同时开启了 SQL Monitor 时，整库导出报 `ClassCastExcepion cannot be cast to OceanBaseStatement` 错误。

* 使用 OBLOADER 时，如果字段中包含特殊的格式字符会遇到报错：`Error: Data too long for column`。

* 控制文件导入时间数据类型数据不一致。

* 使用 OBLOADER 恢复 DDL 时遇到报错：Executing: "drop table \`if\`;" skipped. Reason: Unknown table 'test.if'。

* 导入字符串值包含双引号或斜杠的的标准 CSV 格式出错。
