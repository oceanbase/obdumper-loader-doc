# 控制文件使用指南

> 本文以 OceanBase 导数工具 V4.3.7 的实际行为为准进行核对。

控制文件用于描述一张表在导入或导出过程中的列级处理规则。当文件中的列顺序与表结构不一致、需要忽略某些字段、需要生成常量或序列值、需要对数据进行清洗或脱敏，或使用定长文件时，可以通过控制文件完成。

本文同时适用于 OBLOADER 和 OBDUMPER，但两者的数据流向不同：

- OBLOADER：文件字段 → 列映射或位置解析 → 预处理 → 目标表列。
- OBDUMPER：数据库表列 → 列选择及排序 → 预处理 → 输出文件字段。

如果只想快速上手，先阅读“快速开始”和“控制文件的生效规则”；如果需要处理复杂场景，再查阅列映射、位置定义、预处理函数和条件表达式。

如需分别查看 OBLOADER 和 OBDUMPER 的详细参考信息，请参见 [OBLOADER 控制文件](500.OBLOADER/300.obloader-data-processing/100.obloader-define-control-files.md)和 [OBDUMPER 控制文件](600.OBDUMPER/300.obdumper-data-processing/100.obdumper-define-control-files.md)。

## 功能和适用范围

| 需求 | OBLOADER | OBDUMPER | 核心语法 |
| --- | --- | --- | --- |
| 指定导入文件字段与目标列的对应关系 | 支持 | 不适用 | `map(n)` |
| 调整参与处理的列及其顺序 | 支持 | 支持 | 按所需顺序列出列名 |
| 定义 POS 定长字段 | 支持 | 支持 | `position(...)` |
| 忽略 POS 文件中的占位字节 | 支持 | 不适用 | `_FILLER position(...)` |
| 生成常量或内存序列 | 支持 | 支持 | `CONSTANT`、`SEQUENCE` |
| 使用数据库序列生成值 | 支持 | 不适用 | `DB_SEQUENCE` |
| 字符串、日期、数值等数据清洗 | 支持 | 支持 | 预处理函数 |
| 条件转换 | 支持 | 支持 | `CASE ... WHEN ... END` |
| 敏感字段脱敏、摘要或加解密 | 支持 | 支持 | `MASK`、`SM3_DIGEST`、`SM4_ENCRYPT` 等 |

控制文件可用于 CSV、CUT、SQL、POS、ORC、Parquet 和 Avro 等数据格式。`position` 只用于 POS 定长文件。OBLOADER 使用 `--pos` 导入 POS 文件时必须提供控制文件；OBDUMPER 导出 POS 文件时仍使用 `--cut`，并将列分隔符设置为空字符，通过控制文件定义列长度。DDL 和 MIX 模式不使用控制文件进行数据处理。

## 快速开始

### 导入示例：重排列、清洗数据并补默认值

假设目标表 `customer` 有以下列：

```text
id, name, status, created_at, source
```

待导入文件每行有 4 个字段，依次是 `id`、`name`、`status` 和 `created_at`。需要完成以下处理：

- 删除 `id`、`name` 和 `status` 两端空格。
- 将 `name` 转换为小写。
- 将状态 `A` 和 `I` 分别转换为 `ACTIVE` 和 `INACTIVE`，其他值转换为 `UNKNOWN`。
- 将 `yyyyMMddHHmmss` 格式的时间转换为 `yyyy-MM-dd HH:mm:ss`。
- 目标列 `source` 固定写入 `legacy`。

创建 `customer.ctrl`：

```text
lang=java
(
  id "trim(id)" map(1),
  name "lower(trim(name))" map(2),
  status "case upper(trim(status)) when 'A' then 'ACTIVE' when 'I' then 'INACTIVE' else 'UNKNOWN' end" map(3),
  created_at "to_timestamp(created_at,'yyyyMMddHHmmss','yyyy-MM-dd HH:mm:ss')" map(4),
  source "constant('legacy')"
);
```

将控制文件放在 `/data/controls` 目录，通过 `--ctl-path` 指定该目录：

```shell
./obloader \
  -h xx.x.x.x -P 2883 -u 'test@mysql#cluster_a' -p '******' \
  -D USERA --table customer \
  --csv -f /data/customer.csv \
  --ctl-path /data/controls
```

### 导出示例：调整输出列并脱敏

导出 `customer` 表时，只输出 `id`、`name`、`status` 和 `created_at`，对 `name` 保留第一个字符、脱敏其余字符，并将 `status` 转换为大写：

```text
lang=java
(
  id "none",
  name "mask_show_first_n(name,'X','x','n',1)",
  status "upper(status)",
  created_at "none"
);
```

```shell
./obdumper \
  -h xx.x.x.x -P 2883 -u 'test@mysql#cluster_a' -p '******' \
  -D USERA --table customer \
  --csv -f /data/output \
  --ctl-path /data/controls
```

## 控制文件的生效规则

### 文件名与表名

当 `--ctl-path` 指向目录时，控制文件必须按 `<表名>.ctrl` 命名。控制文件基本名与表名的匹配规则如下：

- MySQL 模式下，匹配规则由目标数据库的 `lower_case_table_names` 变量决定。值为 `0` 时区分大小写，值为 `1` 或 `2` 时不区分大小写。
- Oracle 模式下，未引用的表名按大写归一化后参与匹配。

工具会递归查找 `--ctl-path` 目录下的 `.ctrl` 文件，因此可以按 schema 或业务模块划分子目录。同一次任务中，应确保每张表只有一个可匹配的控制文件。如果多个控制文件解析为同一个 table key，后解析的配置可能覆盖先解析的配置，工具不会报告重复文件错误。

当 OBLOADER 只导入一张表且 `--ctl-path` 直接指向某个 `.ctrl` 文件时，该文件直接用于这张表，不校验控制文件名与表名。

### 启动参数

使用 `--ctl-path <文件或目录>` 启用控制文件。注意以下冲突：

- OBLOADER 中，`--ctl-path` 不能与 `--auto-column-mapping` 同时使用。
- `--ctl-path` 不能与命令行中的列包含、列排除及按数据类型排除等选项同时使用。如需选择列，应统一在控制文件中定义。
- OBLOADER 使用 `--pos` 导入 POS 文件时必须指定 `--ctl-path`。OBDUMPER 导出 POS 文件时使用 `--cut`，将列分隔符设置为空字符，并通过 `--ctl-path` 指定控制文件。

### 如何确认已生效

任务启动后查看日志。成功解析时会出现类似以下日志：

```text
Parse ctrl definition: "/data/controls/customer.ctrl" success
```

常见的未生效日志包括：

```text
The control file: "{}" is unexpected, ignore it
The control file: "{}" is invalid, ignore it.
No valid control file was defined for the table: "..."
```

出现这些日志时，优先检查控制文件基本名是否符合目标库的表名匹配规则、目标表范围、文件后缀、语法和 `--ctl-path` 指向的实际路径。

## 基本语法

一个控制文件的基本结构如下：

```text
lang=java
(
  <column> [position(<start>:<end>) | position(<length>)] ["<function>"] [map(<index>)],
  ...
);
```

关键规则如下：

1. `lang` 必填。当前建议统一使用 `lang=java`。语法也接受 `lang=sql`，二者均使用工具内置的函数执行引擎，并不会把表达式下推到数据库执行。
2. `server` 可选，可设置为 `server=mysql` 或 `server=oracle`，用于选择少数具有模式差异的函数语义。如需设置，将该配置写在 `lang` 配置之后；不填时按 MySQL 语义处理。
3. 列定义放在一对圆括号内，各列之间使用英文逗号分隔，最后一列后不要写逗号。
4. 文件必须以英文分号 `;` 结束。
5. 预处理函数或表达式必须放在英文双引号中，字符串常量使用英文单引号。
6. 关键字和函数名不区分大小写。为了可读性，示例统一使用小写函数名。
7. 控制文件当前不支持 `--` 或 `//` 行内注释。请不要把说明文字写进 `.ctrl` 文件。
8. MySQL 模式下，控制文件列名始终不区分大小写。Oracle 模式下，未使用中括号或反引号的列名按大写归一化后匹配；使用中括号或反引号时保留大小写，必须与数据库列名精确匹配，例如 `` `Order` `` 或 `[Order]`。

## 列定义的语义

### 列名表示什么

在 OBLOADER 中，每个列定义的列名是目标表列名；在 OBDUMPER 中，列名是待查询和输出的源表列名。

只有出现在控制文件中的列才参与本次数据处理。因此，列的选择、排除和输出顺序应通过控制文件统一管理。

### 默认按顺序对应

导入时，如果不写 `map(n)`，普通列默认按控制文件中的定义顺序消费文件字段。生成列不消费文件字段。

例如，文件中依次是 `id,name,status`：

```text
lang=java
(
  id,
  name,
  status,
  source "constant('legacy')"
);
```

`id`、`name`、`status` 分别读取第 1、2、3 个文件字段，`source` 直接生成常量。

### 使用 map(n) 显式映射

`map(n)` 只用于 OBLOADER，表示当前目标列读取文件中第 `n` 个字段，`n` 从 1 开始。

例如，文件中的顺序是 `name,unused,id`，目标表需要 `id,name,name_copy,source`：

```text
lang=java
(
  id map(3),
  name map(1),
  name_copy map(1),
  source "constant('legacy')"
);
```

该示例同时说明：

- 可以调整文件字段顺序。
- 可以跳过不需要的文件字段，例如第 2 个字段 `unused`。
- 多个目标列可以映射同一个文件字段。
- 生成列不需要 `map(n)`。

建议在需要重排、跳过或复用字段时，对所有普通列都显式写出 `map(n)`，避免后续调整列顺序后产生隐性错位。

### 预处理只读取当前列

预处理表达式中的列名表示当前列的输入值，不支持跨列引用。因此，下面的写法不能把 `first_name` 和 `last_name` 两列拼接起来：

```text
full_name "concat(first_name,last_name)"
```

`concat` 的两个参数应该是当前列的变换或常量，例如为当前 `name` 列增加前缀：

```text
name "concat('user_',trim(name))"
```

## POS 定长文件

### 绝对位置

`position(start:end)` 定义字段在一行数据中的起止字节位置。`start` 和 `end` 都从 1 开始，且包含起止位置。

假设每行数据的结构为：

```text
0001ALICE     XXCN
```

- 第 1～4 字节：`id`。
- 第 5～14 字节：`name`。
- 第 15～16 字节：占位字节，不导入。
- 第 17～18 字节：`region`。

```text
lang=java
(
  id position(1:4) "trim(id)",
  name position(5:14) "rtrim(name)",
  _FILLER position(15:16),
  region position(17:18) "upper(region)"
);
```

`_FILLER` 是 POS 导入的占位字段，表示读取但不写入目标表。同一个控制文件中可以定义多个 `_FILLER`。

### 相对长度

`position(length)` 表示当前字段长度为 `length` 字节，起始位置紧接前一个字段。例如：

```text
lang=java
(
  id position(4) "trim(id)",
  name position(10) "rtrim(name)",
  region position(2) "upper(region)"
);
```

为降低维护成本，同一个控制文件建议统一使用绝对位置或相对长度，不要混用。

### 导出 POS 文件时的截断和填充

OBDUMPER 输出 POS 文件时，`position` 同时决定字段宽度：

- 处理后的值超过指定字节数时，工具会截断，并避免在多字节字符中间断开。
- 值长度不足时，在右侧使用空格补齐。
- 值为 `NULL` 时，该字段整体使用空格填充。

POS 位置按字节而不是字符计数。包含中文、Emoji 或其他多字节字符时，必须按任务指定的文件编码计算宽度。

## 生成列

生成列的值不来自当前输入字段。导入时，生成列不消费文件字段。

| 语法 | 作用 | 示例 |
| --- | --- | --- |
| `CONSTANT('value')` | 为每条记录生成相同的字符串 | `source "constant('legacy')"` |
| `SEQUENCE(initial)` | 从 `initial` 开始生成内存序列，默认步长为 1 | `id "sequence(1000)"` |
| `SEQUENCE(initial,increment)` | 从 `initial` 开始，按 `increment` 递增或递减 | `id "sequence(1000,10)"` |
| `DB_SEQUENCE('sequence_name')` | 导入时使用目标数据库序列的 `nextval` | `id "db_sequence('SEQ_CUSTOMER')"` |

`DB_SEQUENCE` 主要用于 Oracle 模式导入，使用前应确保序列已在目标库中存在，并且导入账号有访问权限。序列名必须写在单引号中。

使用内存 `SEQUENCE` 时，可以保证同一任务中生成值的唯一性，但不应依赖并行任务中生成值与原始文件行号之间的严格顺序关系。

## 预处理函数

本节介绍常用函数及其关键行为。完整的函数签名和参数说明，请参见 [OBLOADER 预处理函数](500.OBLOADER/300.obloader-data-processing/200.obloader-preprocessing-functions.md)和 [OBDUMPER 预处理函数](600.OBDUMPER/300.obdumper-data-processing/200.obdumper-preprocessing-functions.md)。

### 组合规则

预处理函数可以嵌套，内层函数先执行。例如：

```text
name "lower(trim(name))"
code "replace(upper(trim(code)),'-','')"
```

第一个表达式先删除两端空格，再转换为小写。第二个表达式依次执行 `trim`、`upper` 和 `replace`。

函数中写出的列名必须是当前列。常量可以作为函数参数，例如 `concat('CN-',trim(code))`。

### 空值、空字符串和异常值

- `NULL` 表示没有值；空字符串 `''` 和只包含空格的字符串不一定等价于 `NULL`。
- `NVL(value,default)` 只在输入为 `NULL` 时返回默认值。
- `NANVL(value,default)` 在输入为 `NULL`、空白字符串或无法识别为数值时返回默认值；数值有效时返回去除两端空格后的值。
- 日期格式、数字参数或十六进制文本不合法时，部分函数会抛出转换异常。导入时，该行通常会进入坏数据处理流程，应结合错误日志和 bad 文件排查。

### 通用和字符串函数

| 函数 | 作用 | 关键说明 |
| --- | --- | --- |
| `NONE` | 不修改当前列 | 可以省略；显式写出时更易读 |
| `LOWER(value)` | 转换为小写 | `NULL` 返回 `NULL` |
| `UPPER(value)` | 转换为大写 | `NULL` 返回 `NULL` |
| `TRIM(value)` | 删除两端空白字符 | 不删除中间空格 |
| `LTRIM(value[,set])` | 从左侧连续删除 `set` 中的字符 | `set` 省略时为单个空格 |
| `RTRIM(value[,set])` | 从右侧连续删除 `set` 中的字符 | `set` 省略时为单个空格 |
| `SUBSTR(value,start[,length])` | 按字符截取子串 | 起始位置从 1 开始；`0` 按 `1` 处理；负数表示从末尾定位 |
| `SUBSTRING(value,start[,length])` | `SUBSTR` 的别名 | 语义与 `SUBSTR` 相同 |
| `LENGTH(value)` | 返回字符数 | `server=oracle` 时空字符串按 `NULL` 语义处理 |
| `LPAD(value,length[,pad])` | 左补齐或截断到指定字符数 | `pad` 默认为空格 |
| `RPAD(value,length[,pad])` | 右补齐或截断到指定字符数 | `pad` 默认为空格 |
| `LPADB(value,byte_length[,pad])` | 左补齐或截断到指定字节数 | `pad` 必须是单字节字符 |
| `RPADB(value,byte_length[,pad])` | 右补齐或截断到指定字节数 | `pad` 必须是单字节字符 |
| `CONCAT(left,right)` | 拼接两个参数 | 参数可以是当前列变换或常量 |
| `REPLACE(value,search,replacement)` | 替换所有匹配子串 | 建议始终显式提供第 3 个参数；传入 `NULL` 会返回 `NULL` |
| `REVERSE(value)` | 反转字符串 | 按字符反转 |
| `CONVERT(value,target_charset)` | 从工具 JVM 默认字符集转换到目标字符集 | 字符集名由 Java Charset 识别 |
| `CONVERT(value,source_charset,target_charset)` | 在指定字符集之间转换 | 转换失败时返回 `NULL` 并记录错误日志 |
| `ASCII(value)` | 返回首个字符的 Unicode 码点数值 | 例如 `ASCII('A')` 返回 `65` |
| `CHR(value)` | 将整数转换为字符 | 输入必须可解析为整数 |
| `NCHR(value)` | 将 Unicode 码点转换为字符 | 输入必须可解析为整数 |
| `RAWTOHEX(value)` | 将字符串字节转换为十六进制文本 | 例如 `hello` 转为 `68656c6c6f` |
| `HEXTORAW(value)` | 将十六进制文本还原为 UTF-8 字符串 | 允许 `0x` 前缀；非法十六进制文本会报错 |

### 空值和数值函数

| 函数 | 作用 | 示例 |
| --- | --- | --- |
| `NVL(value,default)` | 值为 `NULL` 时返回默认值 | `nvl(status,'UNKNOWN')` |
| `NANVL(value,default)` | 值为 `NULL`、空白或非数字时返回默认值 | `nanvl(amount,'0')` |
| `TRUNC(number[,scale])` | 按指定小数位截断数值，不四舍五入 | `trunc(amount,2)` |

### 日期和时间函数

日期格式使用 Java 日期格式字符串，常用字段包括：`yyyy` 表示年，`MM` 表示月，`dd` 表示日，`HH` 表示 24 小时制的时，`mm` 表示分，`ss` 表示秒，`SSS` 表示毫秒。注意 `MM` 和 `mm` 含义不同。

| 函数 | 作用 | 关键说明 |
| --- | --- | --- |
| `SYSDATE` | 返回工具所在机器的当前时间 | 格式为 `yyyy-MM-dd HH:mm:ss` |
| `SYSTIMESTAMP` | 返回工具所在机器的当前时间 | 格式为 `yyyy-MM-dd HH:mm:ss.SSS` |
| `TO_TIMESTAMP(value,source_pattern[,target_pattern])` | 校验并转换时间字符串 | `target_pattern` 默认为 `yyyy-MM-dd HH:mm:ss.SSS`；仅当 `value` 为 `NULL` 时返回 `NULL`，非空值转换失败时报错 |
| `TMSFMT(value,source_pattern,default[,target_pattern])` | 转换时间字符串，失败时返回 `default` | `target_pattern` 可选，默认值为 `yyyy-MM-dd HH:mm:ss.SSS` |
| `DATE_ADD(value,amount,unit[,pattern])` | 为日期增加或减少指定单位 | 支持 `YEAR`、`MONTH`、`WEEK`、`DAY`；默认格式 `yyyy-MM-dd` |
| `TIMESTAMP_ADD(value,amount,unit[,pattern])` | 为时间增加或减少指定单位 | 支持 `YEAR`、`MONTH`、`WEEK`、`DAY`、`HOUR`、`MINUTE`、`SECOND`、`MILLISECOND`；默认格式 `yyyy-MM-dd HH:mm:ss` |
| `DATE_TRUNC(value,unit[,pattern])` | 将日期截断到指定粒度 | 支持 `YEAR`、`MONTH`、`DAY` |
| `TIMESTAMP_TRUNC(value,unit[,pattern])` | 将时间截断到指定粒度 | 支持 `YEAR`、`MONTH`、`DAY`、`HOUR`、`MINUTE`、`SECOND` |
| `YEAR(value)` | 取年 | 输入格式为 `yyyy-MM-dd HH:mm:ss` |
| `MONTH(value)` | 取月 | 返回 `JANUARY`～`DECEMBER` |
| `HOUR(value)` | 取小时 | 输入格式为 `yyyy-MM-dd HH:mm:ss` |
| `MINUTE(value)` | 取分钟 | 输入格式为 `yyyy-MM-dd HH:mm:ss` |
| `WEEK(value)` | 取年内周序号 | 输入格式为 `yyyy-MM-dd HH:mm:ss` |
| `DAY_OF_MONTH(value)` | 取月内日 | 输入格式为 `yyyy-MM-dd HH:mm:ss` |
| `DAY_OF_WEEK(value)` | 取周内星期 | 返回 `MONDAY`～`SUNDAY` |
| `DAY_OF_YEAR(value)` | 取年内日序号 | 输入格式为 `yyyy-MM-dd HH:mm:ss` |

在当前版本中，`YEAR`、`MONTH`、`HOUR`、`MINUTE`、`WEEK` 和 `DAY_OF_*` 系列函数应使用默认输入格式 `yyyy-MM-dd HH:mm:ss`。如果源值为其他格式，请先使用 `TO_TIMESTAMP` 转换为该格式，再进行提取。

OBLOADER 使用 `TO_TIMESTAMP` 处理非空值且转换失败时会抛出异常，将该记录标记为 bad 并写入 `ob-loader-dumper.bad`。任务是否失败取决于最大错误数等配置。

示例：

```text
created_at "to_timestamp(created_at,'yyyyMMddHHmmss','yyyy-MM-dd HH:mm:ss')"
created_at "tmsfmt(created_at,'yyyyMMddHHmmss','1970-01-01 00:00:00','yyyy-MM-dd HH:mm:ss')"
expire_date "date_add(expire_date,30,'DAY','yyyy-MM-dd')"
created_at "timestamp_trunc(created_at,'DAY','yyyy-MM-dd HH:mm:ss')"
```

`SYSDATE` 和 `SYSTIMESTAMP` 使用导数工具所在机器的时钟和时区，不是目标数据库服务器的时钟。对时间精度有要求时，应先确认机器时钟和时区配置。

### 脱敏函数

脱敏函数会按字符类型替换大写字母、小写字母和数字。默认替换字符分别为 `X`、`x` 和 `n`；符号、空格等其他字符保持不变。

| 函数 | 作用 |
| --- | --- |
| `MASK(value[,upper[,lower[,digit]]])` | 脱敏全部大写字母、小写字母和数字 |
| `MASK_FIRST_N(value,upper,lower,digit,n)` | 只脱敏前 `n` 个字符 |
| `MASK_LAST_N(value,upper,lower,digit,n)` | 只脱敏后 `n` 个字符 |
| `MASK_SHOW_FIRST_N(value,upper,lower,digit,n)` | 保留前 `n` 个字符，脱敏其余字符 |
| `MASK_SHOW_LAST_N(value,upper,lower,digit,n)` | 保留后 `n` 个字符，脱敏其余字符 |

示例：

```text
phone "mask_show_last_n(phone,'X','x','*',4)"
name "mask_show_first_n(name,'X','x','n',1)"
id_card "mask_first_n(id_card,'X','x','*',14)"
```

建议对带 `N` 的函数显式写全替换字符和 `n` 参数，避免因参数省略导致实际脱敏范围与预期不一致。

### 摘要和加解密函数

| 函数 | 作用 | 关键说明 |
| --- | --- | --- |
| `SM3_DIGEST(value[,encoding])` | 计算 SM3 摘要 | `encoding` 支持 `HEX` 或 `BASE64`，默认为 `HEX` |
| `SM4_ENCRYPT(value,base64_key[,encoding])` | 使用 SM4 加密 | 密钥参数是 Base64 编码后的密钥；输出默认为 `BASE64`，也可指定 `HEX` |
| `SM4_DECRYPT(value,base64_key[,encoding])` | 使用 SM4 解密 | `encoding` 必须与密文编码方式一致，默认为 `BASE64` |

示例：

```text
id_card "sm3_digest(id_card,'HEX')"
secret "sm4_encrypt(secret,'MDEyMzQ1Njc4OWFiY2RlZg==','BASE64')"
secret "sm4_decrypt(secret,'MDEyMzQ1Njc4OWFiY2RlZg==','BASE64')"
```

加密和解密密钥不应存放在公开仓库、聊天记录或无权限隔离的配置中。使用前应同时验证密钥长度、Base64 编码和密文编码方式。

## 条件表达式

条件表达式用于根据当前列的值选择不同转换结果。支持简单 `CASE` 和搜索 `CASE` 两种形式。

有关条件表达式的独立参考页，请参见 [OBLOADER 条件表达式](500.OBLOADER/300.obloader-data-processing/300.obloader-conditional-expressions.md)和 [OBDUMPER 条件表达式](600.OBDUMPER/300.obdumper-data-processing/300.obdumper-conditional-expressions.md)。

### 简单 CASE

简单 `CASE` 将一个表达式的结果与多个常量依次比较：

```text
CASE <expression>
  WHEN <constant> THEN <result>
  [WHEN <constant> THEN <result> ...]
  [ELSE <result>]
END
```

例如：

```text
lang=java
(
  status "case upper(trim(status)) when 'A' then 'ACTIVE' when 'I' then 'INACTIVE' else 'UNKNOWN' end"
);
```

### 搜索 CASE

搜索 `CASE` 依次判断多个布尔条件：

```text
CASE
  WHEN <condition> THEN <result>
  [WHEN <condition> THEN <result> ...]
  [ELSE <result>]
END
```

例如，将空值归一化为 `UNKNOWN`，将 `A` 和 `B` 保持不变，其他值转换为 `OTHER`：

```text
lang=java
(
  code "case when code is null then 'UNKNOWN' when code in ('A','B') then code else 'OTHER' end"
);
```

数值判断示例：

```text
lang=java
(
  score "case when nanvl(score,'0')>=60 then 'PASS' else 'FAIL' end"
);
```

### 条件运算符

| 类型 | 支持的写法 | 说明 |
| --- | --- | --- |
| 空值 | `IS NULL`、`IS NOT NULL` | 用于判断 `NULL` |
| 集合 | `IN (...,...)`、`NOT IN (...,...)` | `IN` 列表至少写两个常量 |
| 等值比较 | `=`、`!=`、`<>` | 按字符串比较 |
| 大小比较 | `>`、`<`、`>=`、`<=` | 当前实现按长整数解析后比较，不适用于小数或普通字符串 |
| 逻辑与 | `AND`、`&&` | 两个条件都成立 |
| 逻辑或 | `OR`、<code>&#124;&#124;</code> | 任一条件成立 |
| 逻辑非 | `NOT` | 取反后续条件 |
| 整数算术 | `+`、`-`、`*`、`/`、`DIV`、`%`、`MOD` | 按长整数计算 |

使用条件表达式时请注意：

- 只能使用当前列的值、常量和当前列的函数结果，不支持跨列判断。
- 没有任何 `WHEN` 命中且没有 `ELSE` 时，结果为 `NULL`。
- 大小比较使用长整数语义。如果值可能为空白或非数字，建议先用 `NANVL` 转换。
- 整数除法会丢弃小数部分；除数为 0 会导致该条记录处理失败。
- 当前不支持 `XOR`、`BETWEEN` 或 `<=>`，请勿使用。
- 当前不支持通过圆括号对复杂布尔条件进行显式分组。复杂规则建议拆分为多个简单的 `WHEN`，并使用小样本验证结果。

## 常用场景

### 场景一：文件列顺序与表列顺序不同

对所有普通列显式使用 `map(n)`：

```text
lang=java
(
  id map(3),
  name "trim(name)" map(1),
  status "upper(status)" map(4),
  created_at "to_timestamp(created_at,'yyyyMMddHHmmss','yyyy-MM-dd HH:mm:ss')" map(2)
);
```

### 场景二：丢弃文件中的个别字段

分隔文本中不需要为被丢弃的字段定义伪列，直接跳过它的序号：

```text
lang=java
(
  id map(1),
  name map(3),
  status map(5)
);
```

在 POS 文件中，使用 `_FILLER position(...)` 明确占位区域。

### 场景三：日期格式不合法时使用默认时间

如果不合法日期应进入 bad 文件，使用 `TO_TIMESTAMP`：

```text
created_at "to_timestamp(created_at,'yyyyMMddHHmmss','yyyy-MM-dd HH:mm:ss')"
```

如果业务要求以固定时间继续导入，使用 `TMSFMT`：

```text
created_at "tmsfmt(created_at,'yyyyMMddHHmmss','1970-01-01 00:00:00','yyyy-MM-dd HH:mm:ss')"
```

这两种策略会产生不同的数据质量结果，应根据业务要求选择，不要为了降低报错数量而默认吞掉非法日期。

### 场景四：导出时脱敏敏感数据

```text
lang=java
(
  customer_id,
  customer_name "mask_show_first_n(customer_name,'X','x','n',1)",
  phone "mask_show_last_n(phone,'X','x','*',4)",
  id_card "sm3_digest(id_card,'HEX')"
);
```

导出任务应先使用少量数据确认脱敏结果，再执行全量导出。不要只检查任务是否成功，还要检查敏感列是否已按预期转换。

## 限制和注意事项

- 控制文件是列级处理机制，不是 SQL 查询引擎。表达式由导数工具本地执行，不会下推到数据库。
- 表达式只能读取当前列，不支持跨列计算。
- 控制文件不支持行内注释。
- 不要使用 Groovy 脚本表达式；当前版本不将其作为受支持的公开能力。
- 列名以及控制文件基本名与表名的匹配规则取决于数据库模式和标识符写法，具体请参见“控制文件的生效规则”和“基本语法”。
- `LPAD`/`RPAD` 按字符计数，`LPADB`/`RPADB` 和 POS `position` 按字节计数。
- `SYSDATE` 和 `SYSTIMESTAMP` 使用工具所在机器的时钟。
- 条件表达式中的大小比较和算术运算使用长整数语义，不适用于小数精度计算。
- 任何新增或变更的控制文件都应先通过小数据集验证，再用于全量任务。

## 排查问题

| 现象 | 可能原因 | 处理建议 |
| --- | --- | --- |
| 控制文件没有生效 | 控制文件基本名不符合目标库的表名匹配规则 | MySQL 模式下检查 `lower_case_table_names`，Oracle 模式下检查未引用表名的大写归一化结果 |
| 控制文件被忽略 | 任务未选择对应表，或目录中有无关 `.ctrl` 文件 | 核对表选择参数和日志中的 `unexpected, ignore` |
| 启动时报语法错误 | 缺少逗号、右括号或结尾分号，引号不匹配，或文件中写了注释 | 从最小控制文件开始，逐列恢复配置 |
| 导入列值错位 | `map(n)` 序号从 1 开始，或生成列与普通列的消费顺序理解错误 | 为所有普通列显式指定 `map(n)`，并用单行样本核对 |
| POS 字段错位 | 按字符而非字节计算，或文件编码与预期不一致 | 按实际文件编码重新计算每个字段的字节范围 |
| 日期转换失败 | 格式字符串与实际数据不一致，常见为 `MM` 和 `mm` 混淆 | 抽取正常、边界和非法日期分别验证 |
| 非法日期未使用默认值 | 使用了 `TO_TIMESTAMP` | 如业务允许默认值，改用 `TMSFMT` |
| `CASE` 大小比较异常 | 参与比较的值不是长整数 | 改用等值枚举，或在上游完成小数和字符串范围判断 |
| 大量记录进入 bad 文件 | 预处理函数参数不合法，或源数据与假设不符 | 查看首个根因日志，对失败列的原值建立最小复现样本 |
| 导出脱敏结果不符预期 | 替换字符或 `n` 参数省略，或业务对“保留”和“脱敏”的理解相反 | 显式写全 5 个参数，先导出小样本验证 |

## 上线前检查清单

1. 控制文件基本名符合目标库的表名匹配规则，后缀为 `.ctrl`。
2. `--ctl-path` 指向正确的文件或目录。
3. 文件以 `lang=java` 开头，列之间有逗号，文件以 `);` 结束。
4. 文件中没有 `--` 或 `//` 注释。
5. 列选择、列排除和列顺序只在控制文件中配置，没有与冲突的命令行选项同时使用。
6. 导入重排、跳过或复用字段时，所有普通列都已显式配置 `map(n)`。
7. POS 文件的位置已按字节和实际文件编码核对。
8. 所有日期格式均已使用真实样本验证，并明确选择了“报错”或“默认值”策略。
9. 条件表达式没有使用跨列引用、小数大小比较或未支持的运算符。
10. 脱敏、摘要和加解密规则已用小样本核对输出值，密钥未暴露在公开位置。
11. 小数据集任务日志中已出现控制文件解析成功日志。
12. 已抽查实际导入或导出结果，不是只根据任务终态判断成功。
