# 准备数据

本文概述了在将数据导入和导出 OceanBase 数据库时，所需满足的数据文件要求和注意事项。为确保数据成功导入 OceanBase 数据库，您必须确保您的数据符合这些要求。只要遵循本文档的说明，无论使用哪一种导数工具，您都能够产生符合要求的数据文件。

OBDUMPER 导出的单个文件默认大小为 1 GB。当导出的数据超出 1 GB 时，OBDUMPER 将生成一个新的文件并继续写入。

OBLOADER 允许对数据文件进行逻辑拆分。逻辑拆分不会产生任何临时文件。即使遇到大文件（100 GB 以上），程序也可以在很短的时间内完成文件拆分，从而并行解析每一份子文件，然后并发导入到数据库中。因此，您无需启动多个 OBLOADER 进程进行并发导入的操作。

## 文件大小限制

建议不要使用太大的文件。如果您使用的导数工具无法按照文件块导出，请切分文件。

### 切分文件（Linux 或 MacOS）

使用系统内置的切分命令 `split` 将 CSV 文件切分成若干小的文件。

```shell
split [-a suffix_length] [-b byte_count[k|m]] [-l line_count] [-p pattern] [file [name]]
```

示例语句如下：

```shell
split -l 100000 pagecounts-20210723.csv pages
```

本例根据行数切分 `pagecounts-20210723.csv` 文件。假设当前文件大小是 8 GB，且包含 1000 万行数据，以 100,000 行作为条件，将大文件切分成 100 份子文件，每一份子文件的名称以 `pages` 作为后缀且大小将为 80 MB（1,000,000/100,000=100）。

<main id="notice" type='notice'>
<h4>注意</h4>
<p><code>split</code> 命令根据行数切分文件，数据存在换行时可能会出现切分错误。
</p>
</main>

### 切分文件（Windows）

Windows 不提供系统内置的切分工具。请使用第三方的切分工具和脚本用切分大文件。

## 文件格式

OBDUMPER 支持 CSV、SQL 和 Delimited Text 数据格式。SQL 文件必须只包含 INSERT 语句。注意文件格式和文件后缀名并非一个概念。文件格式指文件内容的组织方式。例如，`123.csv` 文件主要存储的是 CSV 格式的数据，使用 `.csv` 作为后缀名是为了识别文件类型。您也可以在 `123.txt` 文件中存放 CSV 格式的数据。虽然这并不影响软件程序解析该数据文件，但可能会使您难以通过文件名辨识文件中的内容。要识别数据格式，请预览部分数据内容。本节将介绍如何辨识数据格式。

### CSV

CSV 格式是最常见且通用的数据格式。除遵守基本格式规范 [RFC4180](https://datatracker.ietf.org/doc/rfc4180) 之外，请确保：

- 您的 CSV 文件不包含特殊字符。

    如果您的 CSV 文件包含定界符、列分隔符和行分隔符或者 NULL 值，请在导出的命令中设置转义符参数，否则生成的 CSV 文件是无法被正确解析。
- 您的 CSV 文件不包含回车符。
- 您了解 CSV 与 Excel 格式的区别。

以下为 CSV 格式示例：

```shell
Name,Age,Occupation,City
John Smith,32,Engineer,New York
Emma Watson,28,Teacher,London
Michael Chen,45,Doctor,San Francisco
Sarah Johnson,39,Lawyer,Chicago
```

其中，CSV Header 为 CSV 文件中第一行，对应表中的列名。您可以选择不插入 Header。CSV Record 是指 CSV 文件中存放的是表中的数据。

### INSERT

为确保 INSERT 语句正确，请确保：

- 您已为包含 SQL 关键字的对象名或者列名进行转义。

    如果您的对象名或者列名是 SQL 关键字，在生成 INSERT 语句时，为对象名或者列名加上转义符号。例如，Oracle 语法使用双引号转义（"），MySQL 语法使用反引号（`）转义。

- 您已为存在单引号的数据进行转义。
  
    如果您的数据中存在单引号，在生成 INSERT 语句时，为数据做特殊字符的转义替换。OBDUMPER 工具导出数据时，默认会对数据做转义处理，以确保生成的是语法正确的 INSERT SQL 语句。

以下为 INSERT 格式示例：

```sql
-- Oracle 语法示例
INSERT INTO "employees" ("Name", "Age", "SELECT", "City") VALUES ('John Smith', 32, 'Engineer', 'New York');

INSERT INTO "employees" ("Name", "Age", "SELECT", "City") VALUES ('Emma O''Brien', 28, 'Teacher', 'London');

INSERT INTO "employees" ("Name", "Age", "SELECT", "City") VALUES ('Michael Chen', 45, 'Doctor', 'San Francisco''s Bay Area');

-- MySQL 语法示例
INSERT INTO `employees` (`Name`, `Age`, `SELECT`, `City`) VALUES ('John Smith', 32, 'Engineer', 'New York');

INSERT INTO `employees` (`Name`, `Age`, `SELECT`, `City`) VALUES ('Emma O\'Brien', 28, 'Teacher', 'London');

INSERT INTO `employees` (`Name`, `Age`, `SELECT`, `City`) VALUES ('Michael Chen', 45, 'Doctor', 'San Francisco\'s Bay Area');
```

### Delimited Text

Delimited Text 格式与 CSV 格式易混淆。CSV 格式的分隔符只能是单个字符，默认是逗号。但 Delimited Text 格式的分隔符可以是一或多个字符。Delimited Text 的基础符号为列分隔符和换行符，没有定界符。您的 Delimited Text 数据中不能包含与基础符号冲突的字符，否则解析错误。例如，数据中有换行，解析会变成两行。

以下为 Delimited Text 格式示例：

```shell
Name|Age|Occupation|City
John Smith|32|Engineer|New York
Emma Watson|28|Teacher|London
Michael Chen|45|Doctor|San Francisco
Sarah Johnson|39|Lawyer|Chicago
```

## 处理半结构化数据

常见的半结构化数据格式为 JSON 和 XML。JSON 和 XML 也是复合的数据定义格式。比如，在 JSON 或者 XML 数据节点中可以存放 CSV 或者 INSERT SQL 语句等任意格式的数据。因此在您准备数据时，必须做好数据的定界和转义。目前文件中存在该类型的数据是无法被正确切分的，所以使用 OBLOADER 导入文件中包含 JSON 或者 XML 类型的数据时，可以调整文件拆分的阈值参数，让程序跳过对文件的自动拆分。

## 处理二进制大对象

您必须将二进制类型的大对象如 RAW、BINARY 和 LOB（Large Object Binary）编码成 16 进制的字符串才能进行文件存储和解析。OBDUMPER 和 mysqldump 等工具默认也是这么处理的。极端场景下，LOB 类型可能存储数百 MB 甚至若干 GB 的数据，这为导入导出工具的性能和存储空间带来巨大的挑战。您在日常的操作中，可以将存在二进制大对象数据类型的表单独进行处理。

## 日期时间类型的处理

在 Oracle 或者 OceanBase 数据库 Oracle 兼容模式下，日期时间相关的数据类型是比较复杂的，而且在使用的过程中也容易犯错，比如精度、格式和时区错误等。

源库导出数据、目标库导入数据都需要设置日期和时间格式，目标库导入时设置的格式应当和源库导出时设置的格式一致。如果不一致，日期和时间类型的数据可能无法被正确地导入。

不同数据库的日期时间类型存在差异。例如，DATE 类型在 MySQL、DB2、Oracle 和 OceanBase 等各个不同的数据库中所表示的日期时间信息是有差异的。请自行查阅数据库文档来解决兼容性的问题，否则可能会出现精度丢失或者写入失败。
