# 多库导入

OBLOADER V4.3.5 及之后版本在兼容原有单独导入行为不变的前提下，新增支持在单次导入任务中一次性导入数据库对象至多个数据库/Schema 中的功能。

## 功能介绍

多个数据库的导入功能是在命令中，根据您指定的对象表达式 `<schema.object>`（例如，`test.table1`、`test1.*`、`*.*`、`test[0-9].tbl`、`test*.table`、`test?.tbl` 等），指定需要导入的对象范围。

多库导入在识别到要将对象导入至多个数据库/Schema 后，会打印导入清单并要求您进行确认，您可以使用 `-y` 跳过确认。

## 功能实现

### 单库模式

当 `--table`、`--view` 等对象参数中不包含特定的数据库/Schema，即不存在英文句号（.）时，认为是单库导入，保持原有行为不变。

### 多库模式

只要任一对象参数值包含特定的数据库/Schema，即存在英文句号（.）时，则进入多库导入模式。例如，`test.table1`、`test1.*` 或 `*.*`。

多库模式下，将一条多库导入命令拆分为多个单库导入子任务。具体说明如下：

* 对 `--table`、`--view` 等对象参数进行解析，分发 `<schema.object>` 至对应数据库/Schema 的子任务中，分别指定导入范围。

* 如果某个对象未包含特定的数据库/Schema（例如，`--table 'db1.tbl1, tbl2' -D 'db2'` 中的 tbl2 对象），则使用 `-D` 指定的默认数据库，其他选项保持不变。

多库模式下，将对象导入至不同的数据库/Schema 中可以等效理解为执行了多个单库导入的任务。示例如下：

```shell
obloader -D test --table 'test1.tbl1,test2.tbl2' ...
-> obloader -D test1 --table tbl1 ...
-> obloader -D test2 --table tbl2 ...

obloader -D test --table 'tbl1,test2.tbl2' ...
-> obloader -D test --table tbl1 ...
-> obloader -D test2 --table tbl2 ...
```

默认导入目录结构匹配多库导出形成的数据集，即数据库/Schema 层级目录。根据待导入数据的目录结构来源和特征，多库导入主要分为以下三种场景。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>不支持数据库名存在 <code>[</code> 或 <code>{</code> 的场景，否则您需要进行转义或特别指定才能够顺利导入。</p>
</main>

* 待导入的目录结构是由 OBDUMPER 形成的。

  假设 OBLOADER 多库导入时指定 `-f ./outputs`，并且 `outputs` 的结构类似于：

  ```shell
  ./outputs/
  └── data
      ├── test
      │   ├── TABLE
      │   │   ├── sample_tbl1.csv
      │   │   ├── sample_tbl1-schema.sql
      │   │   ├── sample_tbl2.csv
      │   │   └── sample_tbl2-schema.sql
      │   └── VIEW
      │       ├── sample_tbl1_view-schema.sql
      │       └── sample_tbl2_view-schema.sql
      └── test1
          ├── TABLE
          │   ├── sample_tbl1.csv
          │   ├── sample_tbl1-schema.sql
          │   ├── sample_tbl2.csv
          │   └── sample_tbl2-schema.sql
          └── VIEW
              ├── sample_tbl1_view-schema.sql
              └── sample_tbl2_view-schema.sql

  7 directories, 12 files
  ```

  此时，如果指定这样的参数进行多库导入 `--table 'test*.*' --view 'test*.*' -f ./outputs`，会根据 `<schema.object>` 定位到对应数据库/Schema 目录下的数据进行导入。

  假设目标 OceanBase 存在 `test`、`test1` 和 `test2` 三个数据库，多库导入会将 `./outputs/data/test` 下的对象导入至 `test` 库中，将 `./outputs/data/test1` 下的对象导入至 `test1` 库中。目标环境中的 `test2` 库由于不存在对应的目录结构，将不会被导入任何数据。

* 待导入的目录结构不是由 OBDUMPER 形成的。

  这种目录结构是由用户自己或其他程序产生的目录结构。如果在这种目录结构下进行多库导入，导入的行为和连续在该目录上执行多次单库导入的效果是一致的。

  假设使用 `--table 'test*.*' --view 'test*.*' -f ./outputs`，并且 `outputs` 的目录结构如下所示：

  ```shell
  ./outputs/
  ├── sample_tbl1.csv
  ├── sample_tbl1-schema.sql
  ├── sample_tbl2.csv
  └── sample_tbl2-schema.sql

  0 directories, 4 files
  ```

  假设目标 OceanBase 存在 `test`、`test1` 和 `test2` 三个数据库，多库导入会将 `./outputs` 下的对象分别导入至目标 OceanBase 的 `test`、`test1` 和 `test2` 库下。

* 在待导入的目录结构不是由 OBDUMPER 形成的基础上，使用了 `--file-regular-expression` 参数。

  `--file-regular-expression` 允许用户使用正则表达式定义规则匹配特定的文件进行导入，并且允许使用捕获组从文件名中提取 Schema 和表名信息。

  假设使用 `--table 'test*.*' --file-regular-expression '(?<schema>[a-z0-9]+)\.(?<table>[a-z_0-9]+)\.csv' -f ./outputs` 进行导入，`outputs` 的目录结构如下所示：

  ```shell
  ./outputs/
  ├── test1.sample_tbl2.csv
  └── test.sample_tbl1.csv

  0 directories, 2 files
  ```

  假设目标 OceanBase 存在 `test`、`test1` 和 `test2` 三个数据库，多库导入会将 `./outputs/test1.sample_tbl2.csv` 导入至 `test1` 库中，将 `./outputs/test.sample_tbl1.csv` 下的对象导入至 `test` 库中。目标环境中的 `test2` 库由于不存在对应的目录结构，将不会被导入任何数据。

## 场景示例

### 场景一：单库导出 + 单库导入（保持原有行为）

* 将 `/output` 导出的 `test` 库导入回 `test`。

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** -D test --csv --table '*' -f /output
    ```

* 将 `/output` 导出的 `test` 库导入至另一个库 `test1`。

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** -D test1 --csv --table '*' -f /output
    ```

### 场景二：多库导出 + 多库导入（按库原样导入）

前置操作：您通过下述命令，多库导出 `test1`、`test2` 和 `test3` 库。

```shell
./obdumper -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** --csv --table 'test[1-3].*' -f /output
```

<main id="notice" type='notice'>
<h4>注意</h4>
<p>多库数据集下，多个数据库文件夹只能导入对应的同名数据库中（例如，<code>test2</code> 文件夹导入 <code>test2</code> 库）。该行为是多库导入模式的默认行为。</p>
</main>

* 导入全部数据库

  * 方式一

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** --csv --table 'test[1-3].*' -f /output
    ```

  * 方式二

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** --csv --table '*.*' -f /output
    ```

  * 方式三

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** --csv --table 'test1.*, test2.*, test3.*' -f /output
    ```

* 仅导入数据库 `test1` 和  `test2`

  * 方式一

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** --csv --table 'test[1-2].*' -f /output
    ```

  * 方式二

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** --csv --table 'test1.*,test2.*' -f /output
    ```

  * 方式三

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** --csv --table 'test1.*' --table 'test2.*' -f /output
    ```

### 场景三：多库导出 + 单库导入（选择其中一个库导入）

导出多个数据库后，将其导入至同一个数据库的关键在于 `-f` 参数，会影响执行多库导入还是单库导入。

前置操作：您通过下述命令，多库导出 `test1`、`test2` 和 `test3` 库。

```shell
./obdumper -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** --csv --table 'test[1-3].*' -f /output
```

* 导出数据集中的 `test2` 导入至 `test2`。该场景执行多库导入逻辑，使用 `test2.*` 来指定库。

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** -D test --csv --table 'test2.*' -f /output
    ```

* 将导出的 `test1` 子目录作为单库输入，导入至目标库 `test` 中。该场景执行单库导入逻辑。

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** -D test --csv --table '*' -f /output/test1
    ```

* 指向根目录并使用 `--table '*'`，将 `test1`、`test2` 和 `test3` 库混合作为单库输入导入至 `test`。该场景执行原有的单库导入逻辑。

    ```shell
    ./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** -D test --csv --table '*' -f /output
    ```

    <main id="notice" type='explain'>
    <h4>说明</h4>
    <p>多个数据库导入至一个数据库，本质执行的是原有单库导入逻辑（由 <code>-f</code> 选择输入目录形态触发）。 </p>
    </main>

### 场景四：租户级导入（按库原样导入）

全量导入全部库的全部对象，包含定义和数据。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>不支持数据库名存在 <code>[</code> 或 <code>{</code> 的场景，否则您需要进行转义或特别指定才能够顺利导入。</p>
</main>

```shell
./obloader -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** --table '*.*' --ddl --csv --all -f /output
```
