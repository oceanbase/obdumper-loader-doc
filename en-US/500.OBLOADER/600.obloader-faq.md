# FAQ

Q: How do I resolve an OOM error when using OBLOADER?

A: First, modify the Java Virtual Machine memory parameters in the `bin/obloader` script. Then, exclude the OpenJDK GC bug.

Q: How do I run OBLOADER in debug mode to troubleshoot issues?

A: Simply run the debugging script in the bin directory. For example, `obloader-debug`.

Q: How do I use OBLOADER to import a data file with a name different from the table name?

A: Specify the absolute path of the data file using the `-f` option in the command line. For example, `--table 'test' -f '/output/hello.csv'`.

Q: Why doesn't the imported data take effect when a control file is configured for the table?

A: The control file name must be the same as the table name, with consistent capitalization. By default, MySQL databases use lowercase table names, while Oracle databases use uppercase table names.

Q: Why are command-line options not correctly parsed when running the OBLOADER script?

A: It may be due to special characters in the command-line parameters. For example, when running OBLOADER on Linux, a greater-than sign (>) in the password is misinterpreted as a redirection character, causing the runtime log to be lost. Therefore, use the appropriate quotation marks based on your operating platform.

Q: When using OBLOADER, when should I enclose parameters in single or double quotes?

A: We recommend that you enclose string parameters in single or double quotes.

* On Windows, use double quotes. For example, `--table "*"`.

* On Linux, use single quotes. For example, `--table '*'`.

Q: What should I do when the external file format does not meet the requirements?

A: Here are the format requirements when importing external files:

* If the external file is an SQL file, it must contain only INSERT statements, without any comments or SET statements. Additionally, the file must contain DDL or DML statements. In this case, use the MySQL source command to import the statements.

* If the external file is a CSV file, it must conform to the standard CSV file format. Specifically, it must contain escape characters, delimiter characters, column separators, and row separators. If the data contains delimiters, specify the escape character.

Q: What do I do when there is no response when logs are output to the console?

A: It may be that the console output is suspended or terminated, blocking log output. Here's how to solve it:

   1. Open the log configuration file `{ob-loader-dumper}/conf/log4j2.xml` and find the following configuration:

      ```sql
      <Logger name="com.oceanbase.tools.loaddump" additivity="false" level="INFO">
      <AppenderRef ref="ConsoleAppender"/>
      <AppenderRef ref="InfoRoutingAppender"/>
      <AppenderRef ref="WarnRoutingAppender"/>
      <AppenderRef ref="ErrorRoutingAppender"/>
      </Logger>
      ```

   2. Remove `<AppenderRef ref="ConsoleAppender"/>` and try running the program again.

Q: Why does OBLOADER fail to start with the error: `Access denied for user 'root'@'xxx.xxx.xxx.xxx'`?

A: By default, OBLOADER relies on the root@sys user and password. If a password has been set for the root@sys user in the cluster, specify the password as the value of the `--sys-password` option.

Q: Why does OBLOADER fail to run with the error: `Over tenant memory limits` or `No memory or reach tenant memory limit`?

A: Increase the memory ratio for global SQL workspaces or decrease the value of `--thread`.

```sql
set global ob_sql_work_area_percentage=30; -- Default 5
```

Q: Why does OBLOADER fail to run when importing a CSV file with line breaks in the data, with the error: `Bad Record`?

A: OBLOADER may have used the UNSAFE mode to split the file by default. You need to modify the JVM environment variables in the script. Open the `obloader` file in the `{ob-loader-dumper}/bin/` directory, find the keyword `PROG_OPTS`, and change `-Dfile.split=UNSAFE` to `-Dfile.split=SAFE`.

Q: Why does OBLOADER fail to run with the error: `No tables are exists in the schema: "xxx"`?

A: The table names specified with the `--table 't1,t2'` option must be defined in the database and must be in the correct case. In MySQL compatible mode of OceanBase Database, table names are stored in lowercase. In Oracle compatible mode of OceanBase Database, table names are stored in uppercase. If a table defined in Oracle is stored in lowercase, enclose the table name in square brackets. For example, `--table '[t1]'` indicates a lowercase table name.

Q: Why does OBLOADER fail to run with the error: `The xxx files are not found in the path: "xxx"`?

A: The name of the data file in the directory specified by `-f` must be the same as the table name and must be in the correct case. In MySQL compatible mode of OceanBase Database, table names are stored in lowercase. In Oracle compatible mode of OceanBase Database, table names are stored in uppercase. For example, if the table name specified by `--table 't1'` is t1, the data file in the directory must be named t1.csv or t1.sql, and cannot be named T1.csv or other names.

Q: Why does OBLOADER fail to run with the error: `The manifest file: "xxx" is missing`?

A: The metadata file MANIFEST.bin is generated by OBDUMPER during export. If another tool is used for export, no metadata file is generated. You can use the `--external-data` option to skip the check for the metadata file.

Q: Why does OBLOADER fail to run when importing data in the delimited text format, with the error: `Index:0, Size:0`?

A: This error is caused by carriage returns or line breaks in the data. Please use the script to remove the carriage returns or line breaks before importing the data.

Q: Why does OBLOADER fail to run when importing KEY-partitioned table data to a logical MySQL database of OceanBase Database in Oracle compatible mode, with the error: `socket was closed by server`?

A: Set the `proxy_mem_limited` parameter and check if there are any external dependencies. By default, ODP has a memory limit of 2 GB. When importing data to a logical MySQL database of OceanBase Database using OBLOADER, you must use the root@proxysys account. The statement to modify the memory limit for the logical database is as follows:

```sql
ALTER proxyconfig SET proxy_mem_limited = xxg
```

Q: Why does OBLOADER fail to run with the error: `Not supported feature or function`?

A: Some features are not supported in OBServer versions earlier than V2.2. If you are using OBServer V2.2 or earlier, set the `useServerPrepStmt` parameter in the `{ob-loader-dumper}/conf/session.config.json` file to `false`, and remove the `set session sql_mode = xxx` statement under the `init_sql.mysql` section.
