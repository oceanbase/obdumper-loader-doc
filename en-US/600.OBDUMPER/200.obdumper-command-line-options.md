# Command-line options

OBDUMPER specifies the information to be exported through command-line options. For more information about the options and usage examples, see **Options** and [Usage examples](100.obdumper-quick-start.md).

## Overview

### Option styles

OBDUMPER parameters support both Unix and GNU styles.

* In the Unix style, options are prefixed with a single hyphen (`-`) and are single-character options. For example: `ps -e`. In this style, options and parameters can be adjacent without a space, such as `-p******`.

* In the GNU style, long options are prefixed with double hyphens (`--`) and can be single-character or string options. For example: `ps --version`. In this style, options and parameters must be separated by a space, such as `--table 'test'`.

### Option categories

OBDUMPER command-line options are categorized into basic options and advanced options.

* Basic options: These are commonly used options, including connection options (database connection mode), functionality options (file format, database object type, storage path), and other options.

* Advanced options: These include functionality options (timestamp format, table/column black/white list filtering, error handling) and performance options.

### Required options

When using OBDUMPER to export data, at least the following options must be specified: connection options, format options, database object type options, and storage path options.

Example:

```shell
$./obdumper -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** -D USERA --csv --table '*' -f /output
```

In this example, `-h`, `-P`, `-u`, `-p`, and `-D` are connection options; `--csv` is a file format option; `--table` is a database object type option; and `-f` specifies the storage path.

#### Compressed export

Derivative Tool V4.3.0 and later versions support compressed export of readable file formats such as CSV, CUT, POS, and SQL. You can configure the following command-line options:

* --compress

  A boolean value indicating whether to compress the exported data.

* --compression-algo

  A string specifying the compression format. Valid values include zstd, zlib, gzip, and snappy. The default value is zstd.

* --compression-level

  An integer specifying the compression level for the specified format. The supported compression levels for each format are as follows:

  * zstd supports levels 1 to 22, with a default value of 3.

  * zlib supports levels -1 to 9, with a default value of -1.

  * gzip and snappy do not support specifying a compression level.

#### Database object types

* --all

  This option is used to export all database object definitions and table data. It is a collection of database object types such as `--trigger` and `--view`. The usage restrictions are based on the specific database object types.

  * When used with `--ddl`, this option indicates exporting all database object definitions. However, for database object types such as `--trigger` that are only applicable to the Oracle compatible mode of OceanBase Database, even if you set `--all --ddl` in the MySQL compatible mode of OceanBase Database, the trigger DDL cannot be exported.

  * When used with `--csv`, `--sql`, or `--cut`, this option indicates exporting all table data in the corresponding format. If you need to export all database object definitions and table data, you can specify the `--all` and `--ddl` options along with any data format option.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>The <code>--all</code> option is mutually exclusive with any other database object option. If both <code>--all</code> and another database object option are specified, the <code>--all</code> option takes precedence. </p>
  </main>

* --table-group *'**table_group_name [,table_group_name...]**'* | --table-group '**\***'

  This option is used to export ***table group*** definitions. Except for not supporting data export, the description is the same as the `--table` option.

* --table *'**table_name [,table_name...]**'* | --table '**\***'

  This option is used to export table definitions or table data. When used with `--ddl`, it indicates exporting only table definitions. When used with any data format option, it indicates exporting only table data. When multiple tables are specified, the table names are separated by commas (,). By default, the names of tables in the Oracle compatible mode of OceanBase Database are exported in uppercase, and the names of tables in the MySQL compatible mode of OceanBase Database are exported in lowercase. For example, in the Oracle compatible mode of OceanBase Database, `--table 'test'` and `--table 'TEST'` both indicate the TEST table. In the MySQL compatible mode of OceanBase Database, `--table 'test'` and `--table 'TEST'` both indicate the test table. If you want to distinguish between uppercase and lowercase, enclose the table name in square brackets ([ ]). For example, `--table '[test]'` indicates the test table, and `--table '[TEST]'` indicates the TEST table. If the table name is specified as an asterisk (*), all table definitions or table data are exported.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>OBDUMPER does not support exporting data from internal tables or internal views of OceanBase Database. </li>
    <li>OBDUMPER V4.1.0 and later versions support exporting the definitions of temporary tables in the Oracle compatible mode of OceanBase Database. </li>
    </ul>
  </main>

  This option is used to export ***trigger*** definitions. Except for not supporting data export, the description is the same as the `--table` option. Currently, this option is only applicable to the Oracle compatible mode of OceanBase Database.

By default, the starting value is set to the current sequence progress when `preserve` is specified, and to the initial value when the table was created when `restart` is specified.

#### File path

* -f '***file_path***', --file-path= '***file_path***'

  Specifies the absolute path on the local disk where the data file is stored.

  parameters: key[=value]&...

* --no-nested-dir

  Exports data in a flat directory structure. All files are exported to the directory specified by the `-f` option, and no subdirectories are generated.

  * upload.buffer.type

    Specifies the buffer type. Valid values: `disk` and `bytebuffer`. The default value is `disk`, which stores data blocks in the disk.   * upload.buffer.size

    Specifies the size of each data block, in bytes. The default value is 64 MB.

  * upload.active.blocks

    Specifies the maximum number of data blocks (which may be uploading or waiting to be uploaded) that can be simultaneously processed by each write thread. The default value is 2. If the number of data blocks exceeds this value, the program will block until a data block is uploaded and removed from the waiting queue.

    Since the `--thread` option limits the maximum number of write threads, you can use the formula `thread * active.blocks * buffer.size` to estimate the buffer space that may be occupied during program execution.

### Performance options

* --page-size ***int_num***

  OBDUMPER V4.0.0 and later versions support this option to specify the size of the task page, that is, the number of rows to be queried each time. The default value is 1000000. For example, 1000000 rows are queried each time.

* --thread ***int_num***

  This option specifies the number of concurrent threads. This option directly corresponds to the number of export threads. The default value is `CPU multiplied by 2`. If the CPU exceeds 16, the maximum value is 32. When multiple database objects are exported, the value of the `--thread` option should not exceed 4. If the number of concurrent threads is too large, it will affect the tool's access to the system tables in the sys tenant, and a timeout error will occur during export.

* --block-size

  This option specifies the threshold for splitting files into blocks. It supports the LONG and STRING data types. If the size of the exported data file exceeds this threshold, other logical subfiles are generated sequentially. The unit is not required when you specify this option. The default unit is MB, and the default value is 0, which indicates an unlimited size. A single object generates a single file. This option does not take effect for the ORC and Parquet formats.

  OBDUMPER V4.1.0 and later versions support splitting by the number of rows. The value of `--block-size` is in the unit of MB or ROW. For example, `--block-size 256ROW` indicates that the size of a single file does not exceed 256 rows. `--block-size 1024` or `--block-size 1024MB` indicates that the size of a single file does not exceed 1024 MB. The 1024M or 1GB format is not supported.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When you use <code>--block-size</code>, <code>-f</code> must be specified as <strong>the path address</strong>.</p>
  </main>

* --parallel-macro ***int_num***

  This option specifies the number of macroblocks that a single thread can process. Default value: 8.

* --mem

  OBDUMPER V4.3.2 and later versions support this option to specify the size of the JVM memory. Supported units: K, M, G, or T. Default value: 4G.
