# Command-line options

OBDUMPER specifies the information to be exported by using command-line options. For more information about the options and usage examples, see **Options** and [Usage examples](100.obdumper-quick-start.md).

## Options

### Option styles

OBDUMPER parameters are designed in both Unix and GNU styles.

* In the Unix style, options are preceded by a single hyphen (`-`) and consist of single characters. For example, `ps -e`. In this style, options and parameters can be separated without spaces, such as in `-p******`.

* In the GNU style, long options are preceded by double hyphens (`--`) and can consist of single characters or strings. For example, `ps --version`. In this style, options and parameters must be separated by spaces, such as in `--table 'test'`.

### Option categories

OBDUMPER command-line options are categorized into basic options and advanced options.

* Basic options: commonly used options for OBDUMPER, including connection options (database connection mode), functional options (file format, database object type, storage path), and other options.

* Advanced options: include functional options (timestamp format, table/column filtering with white/blacklists, error handling) and performance options.

### Required options

When using OBDUMPER to export data, at least the following options must be specified: connection options, format options, database object type options, and storage path options.

Example statement:

```shell
$./obdumper -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** -D USERA --csv --table '*' -f /output
```

In this example, `-h`, `-P`, `-u`, `-p`, and `-D` are connection options; `--csv` is a file format option; `--table` is a database object type option; and `-f` specifies the storage path.

#### Compressed export

Derivative Tool V4.3.0 and later support compressed export of readable file formats such as CSV, CUT, POS, and SQL. You can configure the following command-line options.

* --compress

  A boolean value indicating whether to compress the exported data.

* --compression-algo

  A string specifying the compression format. Valid values: zstd, zlib, gzip, and snappy. Default value: zstd.

* --compression-level

  An integer specifying the compression level for the specified compression format. The supported compression levels for each format are as follows:

  * zstd: 1 to 22. Default value: 3.

  * zlib: -1 to 9. Default value: -1.

  * gzip and snappy do not support specifying the compression level.

#### Database object types

* --all

  Used to export all database object definitions and table data. It is a collection of database object types such as `--trigger` and `--view`. The usage restrictions are determined by the specific database object types.

  * When used with `--ddl`, it indicates exporting all database object definitions. For database object types applicable only to OceanBase Database in Oracle mode, such as `--trigger`, specifying `--all --ddl` in OceanBase Database in MySQL mode will still not export trigger DDL.

  * When used with `--csv`, `--sql`, or `--cut`, it indicates exporting all data in tables in the specified format. If you need to export all database object definitions and table data, you can specify `--all` and `--ddl` with any data format option.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>The <code>--all</code> option is mutually exclusive with any other database object option. If both <code>--all</code> and any other database object option are specified, the <code>--all</code> option will take precedence. </p>
  </main>

* --table-group *'**table_group_name [,table_group_name...\]**'* | --table-group '**\***'

  Used to export ***table group*** definitions. Except for not supporting data export, the description is the same as the `--table` option.

* --table *'**table_name [,table_name...]**'* | --table '**\***'

  Used to export table definitions or table data. When used with `--ddl`, it indicates exporting table definitions only. When used with any data format option, it indicates exporting table data only. When specifying multiple tables, separate the table names with commas (,). By default, table names in OceanBase Database in Oracle mode are exported in uppercase, and table names in OceanBase Database in MySQL mode are exported in lowercase. For example, in OceanBase Database in Oracle mode, `--table 'test'` and `--table 'TEST'` both refer to the TEST table. In OceanBase Database in MySQL mode, `--table 'test'` and `--table 'TEST'` both refer to the test table. If you want to distinguish between uppercase and lowercase, enclose the table name in brackets ([ ]). For example, `--table '[test]'` refers to the test table, and `--table '[TEST]'` refers to the TEST table. If the table name is specified as an asterisk (*), it indicates exporting all table definitions or table data.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>OBDUMPER does not support exporting data from internal tables or internal views in OceanBase Database. </li>
    <li>OBDUMPER V4.1.0 and later support exporting the definitions of temporary tables in OceanBase Database in Oracle mode. </li>
    </ul>
  </main>

* --view *'**view_name [, view_name...]**'* | --view '**\*** '

  Used to export ***view*** definitions. Except for not supporting data export, the description is the same as the `--table` option.

* --trigger *'**trigger_name [, trigger_name...]**'* | --trigger '**\***'

  Used to export ***trigger*** definitions. Except for not supporting data export, the description is the same as the `--table` option. Currently, it is applicable only to OceanBase Database in Oracle mode.

* --obj-user 'user_name [, user_name...]' | --obj-user '*'

  Used to export **user** definitions. Except for not supporting data export, the description is the same as the `--table` option.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <ul>
  <li>
  <p>In <code>--public-cloud</code> mode, the <code>--obj-user</code> option is not supported. </p>
  <li>
  <p>The <code>BECOME USER</code> privilege is not included in the export privileges of OceanBase Database in Oracle mode. By default, it is skipped. </p>
  </ul>
  </main>

  * User requirements: In OceanBase Database in Oracle mode, the login user must be an administrator or a regular user with the `dba_users` privilege. In OceanBase Database in MySQL mode, the login user must be an administrator or a regular user with privileges on the `mysql.user` table.

  * By default, the following users are ignored during export:

    * In OceanBase Database in MySQL mode: `root`, `proxyro`, `standbyro`, `ORAAUDITOR`, and `__oceanbase_inner_drc_user`.

    * In OceanBase Database in Oracle mode: `SYS`, `proxyro`, `standbyro`, `PUBLIC`, `ORAAUDITOR`, `LBACSYS`, and `__OCEANBASE_INNER_DRC_USER`.

* --role 'role_name [, role_name...]' | --role '*'

  Used to export **role** definitions. Except for not supporting data export, the description is the same as the `--table` option.

  <main id="notice" type='notice'>

  Used to export ***sequence*** definitions. Except for not supporting data export, the description is the same as the `--table` option.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>OBDUMPER V4.0.0 and earlier are applicable only to OceanBase Database in Oracle mode. OBDUMPER V4.1.0 and later are applicable to OceanBase Database in MySQL mode and OceanBase Database in Oracle mode. </p>

#### File path

* -f '***file_path***', --file-path= '***file_path***'

  Specifies the absolute path on the local disk where data files are stored.

  <main id="notice" type='explain'>

  </main>

  OBDUMPER supports exporting database object definitions and table data to the local disk, Aliyun OSS, Amazon S3, Tencent COS, and Huawei OBS. The syntax is as follows:

  ```shell

  parameters: key[=value]&...
  ```

  | host | The name of the storage space. <br> When you export data to OSS, S3, COS, or OBS, the host refers to the bucket. For more information, see [OSS Bucket](https://help.aliyun.com/document_detail/31827.html#section-yxy-jmt-tdb). |
  |  path  | The resource path of the storage space. The path** must** start with `/`. |

* --ctl-path '***control_path***'

  Specifies the absolute path on the local disk where the control file is stored. The control file can configure built-in processing functions. Before data export, data will be preprocessed based on the configured functions. For example: case conversion, null check, etc. For more information about the control file, see [Data Processing](300.obdumper-data-processing/100.obdumper-define-control-files.md). When you specify this option in the command line, you must enclose the parameter value in single quotation marks. For example: `--ctl-path '/home/controls/'`.

* --log-path '***log_path***'

  Specifies the output directory for OBDUMPER running logs. If you do not specify this option in the command line, OBDUMPER running logs are output to the directory specified by the `-f` option by default. No redirection is required to output logs unless you have special requirements.

* --no-nested-dir

  Exports flat directory structure. All files are exported to the directory specified by the `-f` option, and no subdirectories are generated.

* When you use the Multipart-Upload method to export data to an object storage service, the local file system is used as the temporary directory by default (you can also use the `--tmp-path` option to specify a temporary directory). The temporary directory is used to store the file blocks. You can modify the following parameters in the OBDUMPER running script to adapt to your actual data export environment.

  * upload.buffer.type

    Specifies the buffer type. Valid values: `disk` and `bytebuffer`. The default value is `disk`, which uses the disk to store the file blocks. The disk space is limited. `bytebuffer` uses the memory to store the file blocks. It has better performance but consumes a large amount of JVM heap memory.

  * upload.buffer.size

    Specifies the size of each file block, in bytes. The default value is 64 MB.

  * upload.active.blocks

    Specifies the maximum number of file blocks (which may be uploading or waiting to be uploaded) that can exist simultaneously for each write thread. The default value is 2. When the number of file blocks exceeds this value, the program will block until a file block is uploaded and removed from the waiting queue.

    Since the `--thread` option limits the maximum number of write threads, you can use the formula `thread * active.blocks * buffer.size` to estimate the buffer space that may be occupied during program execution.

#### Blacklist and whitelist filtering

  * --exclude-table *'**table_name [, table_name...]**'*

### Performance options

* --page-size ***int_num***

  OBDUMPER V4.0.0 and later versions support this option to specify the size of the task page, that is, the number of rows to be queried each time. The default value is 1000000. For example, each query returns 1 million rows.

* --thread ***int_num***

  This option specifies the number of concurrent threads. The value of this option directly corresponds to the number of export threads. The default value is `CPU multiplied by 2`. If the number of CPU cores exceeds 16, the default maximum value is 32. When exporting the definitions of multiple database objects, we recommend that you set the value of the `--thread` option to no more than 4. A large number of concurrent threads may affect the tool's access to system tables in the sys tenant and cause a timeout error during export.

* --block-size

  This option specifies the threshold for splitting files into blocks. It supports the LONG and STRING data types. If the size of the exported data file exceeds this threshold, other logical subfiles are generated in sequence. If you specify this option, you do not need to explicitly specify the unit. The default unit is MB, and the default value is 0, which indicates that the size is unlimited and only one file is generated for an object. This option does not take effect for the ORC and Parquet formats.

  OBDUMPER V4.1.0 and later versions support splitting based on the number of rows. The value of `--block-size` is specified in units of MB or ROW. For example, `--block-size 256ROW` specifies that the size of a single file does not exceed 256 rows. `--block-size 1024` or `--block-size 1024MB` specifies that the size of a single file does not exceed 1024 MB. The 1024M and 1GB formats are not supported.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When you use <code>--block-size</code>, <code>-f</code> must be specified as <strong>the path address</strong>. </p>
  </main>

* --parallel-macro ***int_num***

  This option specifies the number of macroblocks that a thread can process. Default value: 8.

* --mem

  OBDUMPER V4.3.2 and later versions support this option to specify the size of the JVM memory. Supported units: K, M, G, or T. Default value: 4G.
