# Command-line options

OBDUMPER specifies the information to be exported by using command-line options. For more information about the options and usage examples, see **Options** and [Usage examples](100.obdumper-quick-start.md).

## Options

### Option styles

OBDUMPER supports both Unix and GNU styles for parameters.

* In the Unix style, options are prefixed with a single hyphen (`-`), and the option is a single character. For example: `ps -e`. The option and parameter can be separated by no space. For example: `-p******`.

* In the GNU style, long options are prefixed with double hyphens (`--`), and the option can be a single character or a string. For example: `ps --version`. The option and parameter must be separated by a space. For example: `--table 'test'`.

### Option categories

OBDUMPER command-line options are divided into basic options and advanced options.

* Basic options: commonly used options for OBDUMPER, including connection options (database connection mode), functional options (file format, database object type, storage path), and other options.

* Advanced options: include functional options (timestamp format, table/column black/white list filtering, error handling) and performance options.

### Required options

When using OBDUMPER to export data, you must include at least the connection options, format options, database object type options, and storage path options.

Example statement:

```shell
$./obdumper -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** -D USERA --csv --table '*' -f /output
```

In this example, `-h`, `-P`, `-u`, `-p`, and `-D` are connection options; `--csv` is a file format option; `--table` is a database object type option; and `-f` is a storage path option.

#### Compressed export

Derivative Tool V4.3.0 and later support compressed export of readable file formats such as CSV, CUT, POS, and SQL. You can configure the following command-line options to enable compressed export.

* --compress

  A boolean value that specifies whether to enable compressed export.

* --compression-algo

  A string that specifies the compression format. Valid values: zstd, zlib, gzip, and snappy. Default value: zstd.

* --compression-level

  An integer that specifies the compression level for the specified compression format. The supported compression levels for each compression format are as follows:

  * zstd: 1 to 22. Default value: 3.

  * zlib: -1 to 9. Default value: -1.

  * gzip and snappy: Not supported.

#### Database object types

* --all

  Specifies to export the definitions of all database objects and table data. It is a collection of database object types such as `--trigger` and `--view`. The usage restrictions apply to the specific database object types.

  * When you specify this option together with `--ddl`, it indicates to export the definitions of all database objects. For database object types such as `--trigger` that apply only to the Oracle compatible mode of OceanBase Database, the definitions of triggers cannot be exported even if you specify `--all --ddl` in the MySQL compatible mode of OceanBase Database.

  * When you specify this option together with `--csv`, `--sql`, or `--cut`, it indicates to export all data in tables in the corresponding format. If you want to export the definitions of all database objects and table data, you can specify `--all` and `--ddl` and then specify any data format option.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p><code>--all</code> cannot be specified together with any other database object option. If you specify <code>--all</code> together with any other database object option, the command specified by <code>--all</code> will be executed first.</p>
  </main>

* --table-group *'**table_group_name [,table_group_name...\]**'* | --table-group '**\***'

  Specifies to export the definitions of ***table groups***. Except that data cannot be exported, the description applies to the `--table` option.

* --table *'**table_name [,table_name...]**'* | --table '**\***'

  Specifies to export the definitions or data of tables. If you specify this option together with `--ddl`, it indicates to export the definitions of tables. If you specify this option together with any data format option, it indicates to export data of tables. If you specify multiple tables, separate the table names with commas (,). By default, the names of tables in the Oracle compatible mode of OceanBase Database are exported in uppercase and the names of tables in the MySQL compatible mode of OceanBase Database are exported in lowercase. For example, in the Oracle compatible mode of OceanBase Database, `--table 'test'` and `--table 'TEST'` both indicate the TEST table. In the MySQL compatible mode of OceanBase Database, `--table 'test'` and `--table 'TEST'` both indicate the test table. If you want to distinguish the case of table names, enclose the table name in brackets ([ ]). For example, `--table '[test]'` indicates the test table, and `--table '[TEST]'` indicates the TEST table. If you specify * as the table name, it indicates to export the definitions or data of all tables.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>OBDUMPER does not support exporting data of internal tables or internal views of OceanBase Database. </li>
    <li>OBDUMPER V4.1.0 and later versions support exporting the definitions of temporary tables in the Oracle compatible mode of OceanBase Database. </li>
    </ul>
  </main>

* --ctl-path '***control_path***'

  Specifies the absolute path on the local disk where the control file is stored. The control file can configure built-in processing functions. Before data export, the system will preprocess the data based on the configured functions. For example: case conversion, empty value check, etc. For more information about the control file, see [Data processing](300.obdumper-data-processing/100.obdumper-define-control-files.md). When you specify this option in the command line, enclose the parameter value in single quotation marks. For example: `--ctl-path '/home/controls/'`.

* --log-path '***log_path***'

  Specifies the output directory for OBDUMPER running logs. If you do not specify this option, OBDUMPER running logs will be output to the directory specified by the `-f` option by default. In most cases, you do not need to use redirection to output logs.

* --no-nested-dir

  Exports a flat directory structure. All files will be exported to the directory specified by the `-f` option, without generating any subdirectories.

* When you use the Multipart-Upload method to export data to object storage, the local file system is used as the temporary directory by default (you can also use the `--tmp-path` option to specify a temporary directory) to store temporary file blocks. You can modify the following parameters in the OBDUMPER running script to adapt to your actual data export environment.

  * upload.buffer.type

    Specifies the buffer type. Valid values: `disk` and `bytebuffer`. The default value is `disk`, which uses the disk to store blocks. The maximum available disk space limits the number of blocks that can be stored. `bytebuffer` uses memory to store blocks, which has better performance but consumes a large amount of JVM heap memory.

  * upload.buffer.size

    Specifies the size of each block in bytes. The default value is 64 MB.

  * upload.active.blocks

    Specifies the maximum number of blocks (which may be uploading or waiting to be uploaded) that can exist simultaneously for each write thread. The default value is 2. When this value is exceeded, the program will block until one of the blocks is uploaded and removed from the waiting queue.

    Since the `--thread` option limits the maximum number of write threads, you can use the formula `thread * active.blocks * buffer.size` to estimate the buffer space that the program may occupy during runtime.

### Performance options

* --page-size ***int_num***

  In OBDUMPER V4.0.0 and later, this option specifies the size of the task page, that is, the maximum number of rows to be queried each time. The default value is 1000000. For example, each query returns 1 million rows.

* --thread ***int_num***

  This option specifies the number of concurrent threads. The value of this option directly corresponds to the number of export threads. The default value is `CPU multiplied by 2`. If the CPU is greater than 16, the default maximum value is 32. When exporting the definitions of multiple database objects, we recommend that you set the value of this option to no more than 4. A high concurrency level may affect the access of the tool to the system tables in the sys tenant and cause a timeout error during export.

* --block-size

  This option specifies the threshold for splitting a file block. It supports the LONG and STRING data types. If the size of the exported data file exceeds this threshold, other logical subfiles are generated sequentially. The unit is not required when you specify this option. The default unit is MB, and the default value is 0, which indicates an unlimited size and generates only one file for an object. This option does not take effect for the ORC and Parquet formats.

  OBDUMPER V4.1.0 and later support splitting based on the number of rows. The value of `--block-size` is in the unit of MB or ROW. For example, `--block-size 256ROW` indicates that the size of a single file does not exceed 256 rows. `--block-size 1024` or `--block-size 1024MB` indicates that the size of a single file does not exceed 1024 MB. The 1024M and 1GB formats are not supported.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When you use <code>--block-size</code>, you must specify <code>-f</code> as <strong>the path address</strong>. </p>
  </main>

* --parallel-macro ***int_num***

  This option specifies the number of macroblocks that a thread can process. The default value is 8.

* --mem

  OBDUMPER V4.3.2 and later support this parameter. This option specifies the size of the JVM memory. The supported units are K, M, G, and T. The default value is 4G.
