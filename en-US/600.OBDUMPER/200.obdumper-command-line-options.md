# Command-line options

OBDUMPER specifies the information to be exported by using command-line options. For more information about options and examples, see **Option list** and [Examples](100.obdumper-quick-start.md).

## Option introduction

### Option style

OBDUMPER parameters are designed in the Unix or GNU style.

* In the Unix style, a single hyphen (-) is used before the single-character option, such as in `ps -e`. In this style, the option and parameter can be separated by spaces or not, such as `-p******`.

* In the GNU style, double hyphens (--) are used before the single- or multi-character option, such as in `ps --version`. In this style, a space must be placed between the option and parameter, such as `--table 'test'`.

### Option category

The options of the OBDUMPER command can be divided into basic options and advanced options.

* Basic options: commonly used options of OBDUMPER, including connection options (database connection mode), feature options (file format, database object type, storage path), and other options.

* Advanced options: feature options (timestamp format, table/column allow/deny list filtering, error handling), and performance options.

### Required options

To use OBDUMPER to export data, you must specify the connection options, format options, database object type options, and storage path options.

Sample statement:

```shell
$./obdumper -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** -D USERA --csv --table '*' -f /output
```

Here, ` -h`, `-P`, `-u`, `-p`, and `-D` are connection options; `--csv` is a file format option; `--table` is a database object type option; and `-f` specifies the storage path.

#### Compressed export

In V4.3.0 and later, the data export tool supports the compression of CSV, CUT, POS, and SQL files. You can use the following command-line options to configure this feature.

* --compress

  A boolean value that specifies whether to compress the exported file.

* --compression-algo

  A string that specifies the compression format. Valid values: zstd, zlib, gzip, and snappy. Default value: zstd.

* --compression-level

  An integer that specifies the compression level of the compression format. The supported compression levels vary by compression format. Here are the details:

  * The zstd compression format supports levels 1 to 22. Default value: 3.

  * The zlib compression format supports levels -1 to 9. Default value: -1.

  * The gzip and snappy compression formats do not support specifying the compression level.

#### Database object types

* --all

  Identifies that all database object definitions and table data are to be exported. It is a combination of database object types such as `--trigger` and `--view`. For limitations on this option, see the descriptions of the corresponding database object types.

  * When used with `--ddl`, it identifies that all database object definitions are to be exported. For database object types like `--trigger` that are applicable only to the Oracle compatible mode of OceanBase Database, if you specify the `--all --ddl` options in the MySQL compatible mode of OceanBase Database, you still cannot export the DDL statements of triggers.

  * When used with `--csv`, `--sql`, or `--cut`, it identifies that all table data are to be exported in the specified format. If you want to export all database object definitions and table data, you can specify the `--all` or `--ddl` option together with any data format option.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>The <code>--all</code> option is mutually exclusive with any database object option. You cannot specify both. If you specify both the <code>--all</code> option and any database object option, the <code>--all</code> option will take precedence. </p>
  </main>

* --table-group *'**table_group_name [,table_group_name...\]**'* | --table-group '**\***

  Identifies that the ***table group*** definitions are to be exported. It is similar to the `--table` option except that it does not support data export.

* --table *'**table_name [,table_name...]**'* | --table '**\***

  Identifies that the table definitions or table data are to be exported. When used with `--ddl`, it identifies that only table definitions are to be exported. When used with any data format option, it identifies that only table data are to be exported. You can specify multiple tables by separating the table names with commas (,). By default, table names exported from a tenant of the Oracle compatible mode of OceanBase Database are in uppercase, and those exported from a tenant of the MySQL compatible mode of OceanBase Database are in lowercase. For example, in the Oracle compatible mode of OceanBase Database, `--table 'test'` and `--table 'TEST'` both refer to the TEST table, and in the MySQL compatible mode of OceanBase Database, `--table 'test'` and `--table 'TEST'` both refer to the test table. If you want to distinguish between uppercase and lowercase, enclose the table name in square brackets ([ ]). For example, `--table '[test]'` refers to the test table, and `--table '[TEST]'` refers to the TEST table. If you specify an asterisk (*) for the table name, it identifies that all table definitions or table data are to be exported.

    </ul>
  </main>

#### Storage path

* -f '***file_path***', --file-path= '***file_path***'

  Specifies the absolute path of a local disk where data files are stored.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>OBDUMPER V4.2.7 and later allow you to specify <code>-f</code> as the specific file name when you export a single file. <ul><li>If you specify <code>--query-sql</code>, <code>CUSTOM_SQL</code> is replaced with the specified file name.</li><li>The <code>log</code> directory is generated in the parent directory of the path specified by <code>-f</code>.</li></ul></p>
  </main>

  OBDUMPER allows you to export database object definitions and table data to a local disk, [Aliyun OSS](https://help.aliyun.com/document_detail/31817.html?spm=5176.8465980.help.dexternal.4e701450fT87ve), [Amazon S3](https://docs.aws.amazon.com/zh_cn/s3/index.html), Tencent COS, and Huawei OBS. The syntax is as follows:

  ```shell
  [scheme://host]path[?parameters]

  parameters: key[=value],...
  ```

  |  **Component** |**Description**|
  |----------------------------------|--------------------------------------------------------|
  |  scheme | The supported storage types, including Aliyun OSS, Amazon S3, Tencent COS, and Huawei OBS.<br> If the specified scheme is not one of the supported types, an error is returned.|
  | host | The name of the storage space.<br>When you export data to [OSS](https://help.aliyun.com/document_detail/31827.html#section-yxy-jmt-tdb), [Amazon S3](url-placeholder/2c789bc4-8d3c-4aa4-927f-3c5969d1536a), Tencent COS, or Huawei OBS, the host specifies the bucket. |
  |  path  | The resource path of the storage space. The path **must** start with `/`. |
  |  parameters  | The parameters required for the request.<br>parameters can be a single key or a key-value pair. |

  The following table describes the parameters.

  |**Parameter** |**Required**|**Description**|**Supported storage types**|**Supported versions**|
  |--------|-------|-------|-------|-------|
  | endpoint  |Yes |<ul><li>The endpoint of the region where the OSS host is located.</li><li>The endpoint can be used to access S3, COS, and OBS services through domain name.</li></ul>|OSS/S3/COS/OBS|<ul><li>OSS: V4.2.0</li><li>S3: V4.2.5</li><li>COS/OBS: V4.3.0</li></ul>|
  | region |Yes |The endpoint specifies the physical location where the bucket is located. |S3/COS/OBS|<ul><li>S3: V4.2.0</li><li>COS/OBS: V4.3.0</li></ul>|
  | storage-class |Yes |The Amazon S3 storage class. |S3|4.2.0|
  | access-key  |Yes |The access account for the storage. |OSS/S3/COS/OBS|<ul><li>OSS/S3: V4.2.0</li><li>COS/OBS: V4.3.0</li></ul>|
  | secret-key  |Yes |The access key for the storage. |OSS/S3/COS/OBS|<ul><li>OSS/S3: V4.2.0</li><li>COS/OBS: V4.3.0</li></ul>|

  Here are some examples:

  * Export data to a local disk

    ```shell
    -f '/home/admin/foo/bar' 
    ```

  * Export data to S3

    ```shell
    -f 's3://bucket/path?region={region}&access-key={accessKey}&secret-key={secretKey}'
    ```

  * Export data to OSS

    ```shell
    -f 'oss://mybucket/foo/bar?endpoint=myendpoint&access-key=myak&secret-key=mysk' 
    ```

  * Export data to COS

    ```shell
    -f 'cos://mybucket/foo?region=ap-shanghai&access-key=myak&secret-key=mysk'
    -f 'cos://mybucket/foo?endpoint=yourendpoint&access-key=myak&secret-key=mysk'
    ```

  * Export data to OBS

    ```shell
    -f 'obs://mybucket/foo?region=cn-north-1&access-key=myak&secret-key=mysk'
    -f 'obs://mybucket/foo?endpoint=yourendpoint&access-key=myak&secret-key=mysk'
    ```

* --ctl-path '***control_path***'

  Specifies the absolute path of a local disk where control files are stored. You can configure built-in processing functions in control files. Before data is exported, the data is preprocessed based on the configured functions. For example, the functions can be used for case conversion and null value judgment. For more information about the use of control files, see [Data processing](300.obdumper-data-processing/100.obdumper-define-control-files.md). If you specify this option in the command line, enclose the parameter value in single quotation marks. For example, `--ctl-path '/home/controls/'`.

* --log-path '***log_path***'

  Specifies the output directory of OBDUMPER running logs. If you do not specify this option in the command line, OBDUMPER running logs are output to the directory specified by the `-f` option. In most cases, you do not need to redirect the logs.

* --no-nested-dir

  Specifies to export the files to a flat directory structure. All files are exported to the directory specified by `-f`, and no subdirectories are created.

* When OBDUMPER exports data to object storage services, it uses the Multipart-Upload method by default. The local file system is used as the temporary directory (which can be specified by using the `--tmp-path` option) to store file blocks. You can modify the following parameters in the OBDUMPER script to adapt to your actual export environment.

  * upload.buffer.type

    Specifies the buffer type. Valid values: `disk` and `bytebuffer`. The default value is `disk`. If `disk` is specified, file blocks are stored in the disk, which is limited by the maximum available disk space. If `bytebuffer` is specified, file blocks are stored in memory. This performs well but occupies a large amount of JVM heap memory.

  * upload.buffer.size

    Specifies the size of each file block in bytes. The default value is 64 MB.

  * upload.active.blocks

    Specifies the maximum number of file blocks that each write thread can have at the same time, which can be uploading or waiting in the queue. The default value is 2. If the number of file blocks exceeds this value, the program is blocked until a file block is uploaded and removed from the queue.

    The `--thread` option limits the maximum number of write threads. You can estimate the buffer space occupied by the program when it is running by using the formula `thread * active.blocks * buffer.size`.

### Performance options

* --page-size ***int_num***

  In OBDUMPER V4.0.0 and later, this option specifies the number of rows returned in each query for a task. The default value is 1000000. For example, 1000000 rows are returned in each query.

* --thread ***int_num***

  This option specifies the number of concurrent threads. This option directly corresponds to the number of export threads. The default value is `2 × CPU`. If the CPU number exceeds 16, the default maximum value is 32. When you export multiple database objects at a time, we recommend that you do not set the value of the `--thread` option to a number greater than 4. If the number of concurrent threads is too large, the tool may experience timeouts when accessing system tables in the sys tenant.

* --block-size

  This option specifies the threshold for splitting file blocks. It takes effect for the LONG and STRING data types. If the size of the exported data file exceeds the specified threshold, the tool generates other logical subfiles sequentially. When you use this option, you do not need to specify the unit. The default unit is MB. The default value is 1024 MB. This option does not take effect for the ORC and Parquet formats.
  In OBDUMPER V4.1.0 and later, you can also split file blocks by row count. The value of `--block-size` is a numeric value, where MB indicates storage size and ROW indicates row count. For example, `--block-size 256ROW` specifies that a file contains no more than 256 rows. `--block-size 1024` or `--block-size 1024MB` specifies that a file contains no more than 1024 MB. This value does not support 1024M or 1GB.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>If you use the <code>--block-size</code> option, you must specify the value of <code>-f</code> as a <strong>path address</strong>. </p>
  </main>

* --parallel-macro ***int_num***

  This option specifies the number of macroblocks that a thread can process. The default value is 8.

### Other options

* --session-config

  Specifies the [connection configuration](../800.obloaderobdumper-session-variables.md) file. The package provides a default configuration file: `session.config.json` in the `conf` directory. You can use the default configuration file without any settings. We recommend that you specify this option only when you want to use the same package to load multiple connection configurations.

  Retains the schema information for the exported tables and synonyms. By default, the exported DDL statements do not contain schema information and include only the table names. If you specify the `--retain-schema` option, the schema names are retained in the `schema.table` format.
