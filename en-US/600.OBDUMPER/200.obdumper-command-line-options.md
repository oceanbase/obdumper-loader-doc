# Command-line options

OBDUMPER specifies the information to be exported by using command-line options. For more information about the options and usage examples, see **Options** and [Usage examples](100.obdumper-quick-start.md).

## Options

### Option styles

OBDUMPER supports both the Unix and GNU styles for options.

* In the Unix style, options are prefixed with a single hyphen (`-`), and the option is a single character. For example: `ps -e`. In this style, you can omit the space between the option and the parameter. For example: `-p******`.

* In the GNU style, long options are prefixed with double hyphens (`--`), and the option can be a single character or a string. For example: `ps --version`. In this style, you must add a space between the option and the parameter. For example: `--table 'test'`.

### Option categories

OBDUMPER command-line options are divided into basic options and advanced options.

* Basic options: These are commonly used options, including connection options (database connection mode), functional options (file format, database object type, storage path), and other options.

* Advanced options: These include functional options (timestamp format, table/column black-and-white list filtering, error handling) and performance options.

### Required options

When you use OBDUMPER to export data, you must specify at least the connection options, format options, database object type options, and storage path options.

Example:

```shell
$./obdumper -h xx.x.x.x -P 2883 -u test@mysql#cluster_a -p ****** -D USERA --csv --table '*' -f /output
```

In this example, `-h`, `-P`, `-u`, `-p`, and `-D` are connection options; `--csv` is a file format option; `--table` is a database object type option; and `-f` is a storage path option.

#### Compressed export

In Derive V4.3.0 and later, you can export readable files such as CSV, CUT, POS, and SQL in a compressed format. You can configure the following command-line options to perform the compressed export.

* --compress

  A boolean value that specifies whether to compress the exported data.

* --compression-algo

  A string that specifies the compression format. Valid values are zstd, zlib, gzip, and snappy. The default value is zstd.

* --compression-level

  An integer that specifies the compression level for the specified compression format. The supported compression levels for each compression format are as follows:

  * zstd: 1 to 22. The default value is 3.

  * zlib: -1 to 9. The default value is -1.

  * gzip and snappy: Not supported.

#### Database object types

* --all

  Specifies to export the definitions of all database objects and table data. It is a collection of database object types such as `--trigger` and `--view`. For more information about the usage restrictions, see the specific database object types.

  * When this option is used with `--ddl`, the definitions of all database objects are exported. For database object types such as `--trigger` that are only supported in the Oracle compatible mode of OceanBase Database, the definitions of triggers cannot be exported even if you specify `--all --ddl` in the MySQL compatible mode of OceanBase Database.

  * When this option is used with `--csv`, `--sql`, or `--cut`, the data in all tables is exported in the specified format. To export the definitions of all database objects and table data, you can specify `--all` and `--ddl` with any of the data format options.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p><code>--all</code> cannot be used with any database object option. If you specify <code>--all</code> and any database object option, the command specified by <code>--all</code> is executed first.</p>
  </main>

* --table-group *'**table_group_name [,table_group_name...\]**'* | --table-group '**\***'

  Specifies to export the definitions of ***table groups***. Except for the inability to export data, the description is the same as that of the `--table` option.

* --table *'**table_name [,table_name...]**'* | --table '**\***'

  Specifies to export the definitions or data of tables. When this option is used with `--ddl`, the definitions of tables are exported. When this option is used with `--csv`, `--sql`, or `--cut`, the data in tables are exported. If you specify multiple tables, separate the table names with commas (,). By default, the names of tables in the Oracle compatible mode of OceanBase Database are exported in uppercase and the names of tables in the MySQL compatible mode of OceanBase Database are exported in lowercase. For example, in the Oracle compatible mode of OceanBase Database, `--table 'test'` and `--table 'TEST'` both specify the TEST table. In the MySQL compatible mode of OceanBase Database, `--table 'test'` and `--table 'TEST'` both specify the test table. If you want to distinguish between uppercase and lowercase letters, enclose the table name in square brackets ([ ]). For example, `--table '[test]'` specifies the test table and `--table '[TEST]'` specifies the TEST table. If you specify * as the table name, the definitions or data of all tables are exported.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>OBDUMPER does not support exporting the data of internal tables or internal views in OceanBase Database. </li>
    <li>Starting from OBDUMPER V4.1.0, OBDUMPER supports exporting the definitions of temporary tables in the Oracle compatible mode of OceanBase Database. </li>
    </ul>
  </main>

  </main>

* --ctl-path '***control_path***'

  Specifies the absolute path of the local disk where the control file is stored. You can configure built-in processing functions in the control file. Before data is exported, the configured functions are used to preprocess the data. For example, case conversion and null check. For more information about how to use the control file, see [Data Processing](300.obdumper-data-processing/100.obdumper-define-control-files.md). When you specify this option in the command line, you must enclose the parameter value in single quotation marks. For example: `--ctl-path '/home/controls/'`.

* --log-path '***log_path***'

  Specifies the output directory of the OBDUMPER running log. If you do not specify this option, the OBDUMPER running log is output to the directory specified by the `-f` option by default. In most cases, you do not need to use redirection to output logs.

* --no-nested-dir

  Exports a flat directory structure. All files are exported to the directory specified by the `-f` option, without generating any subdirectories.

* When you use the Multipart-Upload method to export data to an object storage service, the local file system is used as the temporary directory by default (you can also use the `--tmp-path` option to specify a temporary directory). The temporary directory is used to store the data blocks. You can modify the following parameters in the OBDUMPER running script to adapt to your actual export environment.

  * upload.buffer.type

    Specifies the buffer type. Valid values: `disk` and `bytebuffer`. The default value is `disk`, which stores data blocks on the disk. The disk space is limited. `bytebuffer` stores data blocks in memory. This method has better performance but consumes a large amount of JVM heap memory.

  * upload.buffer.size

    Specifies the size of each data block, in bytes. The default value is 64 MB.

  * upload.active.blocks

    Specifies the maximum number of data blocks that can be simultaneously written by each write thread. The default value is 2. If the number of data blocks exceeds this value, the program will be blocked until one of the data blocks is uploaded and removed from the waiting queue.

    Since the `--thread` option limits the maximum number of write threads, you can use the formula `thread * active.blocks * buffer.size` to estimate the buffer space that may be occupied during program running.

#### Whitelist and blacklist filtering

  * --exclude-table *'**table_name [, table_name...]**'*

    * All tables whose names end with test

    * All tables whose names start with te and end with st

### Performance options

* --page-size ***int_num***

  OBDUMPER V4.0.0 and later versions support this option, which specifies the size of the task page, that is, the number of rows to be queried each time. The default value is 1000000. For example, 1 million rows are queried each time.

* --thread ***int_num***

  This option specifies the number of concurrent threads. The value of this option directly corresponds to the number of export threads. The default value is `CPU multiplied by 2`. If the CPU is greater than 16, the default maximum value is 32. When multiple database objects are exported, the value of the `--thread` option should not exceed 4. A large number of concurrent threads may affect the tool's access to system tables in the sys tenant, resulting in a timeout error during export.

* --block-size

  This option specifies the split threshold of a file block. It supports the LONG and STRING data types. If the size of the exported data file exceeds the threshold, other logical subfiles are generated sequentially. The unit is not required when you specify this option. The default unit is MB, and the default value is 0, which indicates an unlimited size (a single object generates a single file). This option does not take effect for the ORC and Parquet formats.

  OBDUMPER V4.1.0 and later versions support splitting by the number of rows. The value of `--block-size` is specified in units of MB or rows. For example, `--block-size 256ROW` indicates that the size of a single file does not exceed 256 rows. `--block-size 1024` or `--block-size 1024MB` indicates that the size of a single file does not exceed 1024 MB. The 1024M or 1GB format is not supported.

  <main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When you use <code>--block-size</code>, <code>-f</code> must be specified as <strong>the path address</strong>.</p>
  </main>

* --parallel-macro ***int_num***

  This option specifies the number of macroblocks that a thread can process. Default value: 8.

* --mem

  OBDUMPER V4.3.2 and later versions support this option, which specifies the size of the JVM memory. Supported units: K, M, G, or T. Default value: 4G.

We recommend that you specify this option only when you need to use the same configuration file directory to load multiple connection configurations.
