# Derivative tool V4.3.3.1

Derivative tool V4.3.3.1 released in April aims to fix the critical bugs reported by users who use the version V4.3.3 or earlier.

## Considerations

**When you upgrade the Data Export Tool from a version earlier than V4.3.0, note the following:**

* To reduce the learning curve, the following adjustments have been made to the command-line options:

  * The command-line option `--storage-uri` has been deprecated. Its original functionality has been merged with `-f`/`--file-path`.

    Please note that the option can still be used after it has been deprecated. We recommend that you use one of the following methods as a replacement:

    * If you use the local file system, specify `-f '/home/admin/foo/bar'`.

    * If you use Alibaba Cloud Object Storage Service (OSS), specify `-f 'oss://mybucket/foo/bar?endpoint=myendpoint&access-key=myak&secret-key=mysk'`.

    When you export database object definitions and table data to a non-local file system, the Data Export Tool will create a temporary directory by default as `<root directory of the tool>/tmp` to store temporary files. If you want to specify a temporary directory, use the `--tmp-path` option.

  * The `--compact-schema` option is set to `true` by default. When OBServer V4.0.0 or later exports data, if this option is specified, the tool will use the `SHOW CREATE TABLE ...` statement to obtain the DDL, instead of querying the system view and reverse-engineering the DDL (the default schema export strategy).

     This modification is made to be compatible with some standard view changes of OBServer, to improve overall performance, and to support new columnar storage features. You can still use the default schema export strategy by specifying `--compact-schema=false`.

* If the size of the data in a table is smaller than the specified block size (specified by `--block-size`, with a default value of 1 GB), the file will be named `<table name>.<extension>`, instead of `<table name>.<sequence number of the block>.<extension>`. For example, when you export CSV files:

  * If the table `t_test` contains 500 MB of data and the `--block-size` option is set to its default value of 1 GB, only one file named `t_test.csv` will be generated.

  * If the table `t_test` contains 1.2 GB of data and the `--block-size` option is set to its default value of 1 GB, two files named `t_test.0.csv` and `t_test.1.csv` will be generated.

**When you upgrade the Data Export Tool from a version earlier than V4.2.8, note the following:**

* At present, you can specify a value in the `<user>@<tenant>#<cluster>` format for the `-u/--user` option. To ensure compatibility with earlier versions, you can also use the `-t/--tenant` and `-c/--cluster` options.

* The behavior for parsing POS files has changed. The parser now processes a complete line. In other words, in addition to the byte length defined in the control file, each line is read with an extra line break. You may need to modify the control file to adapt to this change. You can use the following command to calculate the number of bytes in the first line of the `example.dat` file:

   ```shell
   expr $(head -n 1 example.dat | wc -c) - 1
   ```

**When you upgrade the Data Export Tool from a version earlier than V4.2.7, note the following:**

* The `--file-name` option is deprecated.

  * You no longer need to merge multiple sub-files generated for a single table. If you want to write the data of a table to a single file, you can set `--block-size 0` to prevent the tool from splitting the table data into multiple files.

    Please note that although the tool does not limit the file size, the file size is limited by the file system or object storage service in practice. For example, in the ext2, ext3, and ext4 file systems, the size of a single file is limited to 2 TB.

  * If you want to remove the complex hierarchical directory structure generated by default, you can use the `--no-nested-dir` option.

* The `--upload-behavior` option is deprecated. For write strategies for different data sources, see the feature description.

* Due to significant changes in file write behavior in the Data Export Tool V4.2.7, the tool will deliberately reduce its performance to ensure the predictability of the number of exported files. If you find that the export performance is poor, the tool provides a concurrency switch. With this switch enabled, the tool will still write the data of each table to multiple files, as in earlier versions, but it will not merge the sub-files. To enable this switch, perform the following operations:

   1. Open the `obdumper` file in a text editor. The path of this file is: `<root directory of the tool>/bin/obdumper`.

   2. Find the Java startup parameter `-Denable.parallel.write=false` and change its value to `true`.

## New features

* The `--retain-schema` option is provided.

   By default, the exported DDL does not contain schema information and only includes table names. With the `--retain-schema` option specified, `schema.table` names are retained.

## Bug fixes

* Fixed the issue where the program cannot be properly terminated when an error occurs during export on Windows.

* Fixed the issue where an error "command line too long, incorrect syntax" is returned when the command line is too long during import or export on Windows.

* Fixed the issue where a table schema is missing foreign keys when the `--no-sys` option is specified during the export of OceanBase Database V3.x and earlier.

* Fixed the issue where virtual column definitions are incorrect when the `--no-sys` option is specified during the export of OceanBase Database V3.x and earlier.

* Fixed the issue where an index creation statement is repeated when the table schema contains UNIQUE FUNCTION constraints.

* Fixed the issue where a syntax error is returned when the export of OceanBase Database V4.3.5.1 contains new table options.

* Fixed the issue where a NumberFormatException is thrown during the export of binary data in the Oracle compatible mode of OceanBase Database.

* Fixed the issue where the error "unknown" is returned when the partition information of a table group is queried by using DDL.

* Fixed the issue where the auto-increment hidden primary key fails to be created during the export with the `--enable-hidden-pk` option specified.

* Fixed the issue where the export of TIME values in the MySQL compatible mode of OceanBase Database V3.x and V4.x exceeds 24:59:59.

* Fixed the issue where the export of table schemas with a concurrency level higher than 3 fails.

* Fixed the issue where an error is returned when a Parquet or ORC file is imported from a path that contains special characters.

* Fixed the issue where the `sql-monitor.log` file is not generated during import.

* Fixed the issue where the error "Truncated incorrect DOUBLE value" is returned without generating the `ob-loader-dumper.bad` file.

* Fixed the issue where an error is returned when a table whose name starts with recycle is imported.

* Fixed the issue where a NullPointerException is thrown when a required parameter is missing during import or export.

* Fixed the issue where the error "Invalid sys-password specified" is returned when the password specified for the sys tenant is incorrect, but the task exits with a status of System exit 0.

* Fixed the issue where a file with a secondary name is exported when parallel write and compression are enabled, which makes the file invalid for import.

* Fixed the issue where single quotation marks cannot be specified as escape characters when the load data statement is used in the Oracle compatible mode of OceanBase Database.

* Fixed the issue where a syntax error is returned when the data of a table with the ORGANIZATION table option is exported.

* Fixed the issue where the error "java. Lang. NumberFormatException: For input string: " -"" is returned.

* Fixed the issue where case-insensitive recognition of brackets does not take effect.

## Known issues

* The exported database object definitions may contain the name of the database to which the object belongs.

* Exporting PL object definitions is not supported in OceanBase Database MySQL compatible mode of versions earlier than V2.2.30.

* If the password of the sys tenant is not specified on the command line, exporting table group definitions is not supported in OceanBase Database versions earlier than V2.2.70.

* If the password of the sys tenant is not specified on the command line, exporting index definitions is not supported in the Oracle compatible mode of OceanBase Database versions earlier than V2.2.50.

* If the password of the sys tenant is not specified on the command line, exporting partition information of unique indexes is not supported in the Oracle compatible mode of OceanBase Database versions earlier than V2.2.70.

* If the password of the sys tenant is not specified on the command line, exporting unique index definitions of partitioned tables is not supported in OceanBase Database V2.2.70 and later.

* When using OBLOADER to import data, if the specified file format (such as `--sql` or `--csv`) does not match the actual file format, an error occurs.

* After case sensitivity is enabled for the MySQL compatible mode of OceanBase Database, database object names such as tables and views no longer support strict case matching.

* The JDBC high-availability mode "sequential" is temporarily unavailable. You can use the "loadbalance" mode instead.

* When the `--remove-newline` option is specified to remove line breaks, unexpected escape characters are generated. We recommend that you do not use this option.

* Bypass import is not recommended in multi-table restore scenarios, as it may not be efficient.

## Considerations

* In a CUT file, each data record is stored in an entire line. When you use the `--cut` option of the OBDUMPER command line, if the specified field separator is a single character, OBDUMPER escapes special characters in the data, such as separators, carriage returns, and line breaks. For example, if the data is `abc|def` and the separator is `|`, the exported data is `abc\|def`.

* When you use the `--logical-database` option in the command line, the definition of a random physical database shard is exported. You cannot directly import the definition into a database. You need to manually convert the exported physical database shard definition into a logical one before you import it into the database for business use.

* When you use the `--add-extra-message` option to export table definitions, the name of the table group to which each table belongs is exported. This option depends on the privileges of the sys tenant. If OBDUMPER does not have the privileges of the sys tenant, do not use this option.

* Before you use OceanBase Database V3.2.4.0 or later to export data, set the system parameter `open_cursors` to a large value. Otherwise, an error may occur during the import or export. After the data is imported or exported, reset the system parameter to the initial value, for example, `ALTER SYSTEM SET open_cursors = 65535;`.

* If the schema of a table has been changed in OceanBase Database V4.0.0.0 or later, you cannot use OBDUMPER to export the baseline data, namely the consistent snapshot data, obtained after the last major compaction. You can manually initiate a major compaction and then re-export the most recent baseline data.

* In the MySQL compatible mode of OceanBase Database, the export tool can export zero values/dates and times. However, when zero values/dates and times are exported, you cannot determine whether the original data is NULL or zero values. You can use the `--preserve-zero-datetime` option to forcibly convert the data to zero values. In addition, zero values exported as DATETIME or TIMESTAMP data types may be distorted into non-zero approximate values. An error will be reported when you import zero value data if the `sql_mode` variable contains the NO_ZERO_DATE or NO_ZERO_IN_DATE constraint.

    In the MySQL compatible mode of OceanBase Database, data types that involve zero value issues include DATE, DATETIME, TIME, YEAR, and TIMESTAMP.
